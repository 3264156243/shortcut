# ShortCut 协同开发规范（多端并行）

> 适用对象：同时参与本仓库的**桌面端/服务端/移动 Web** 与**安卓端（原生 Kotlin）**开发者。
> 目的：让两个人可以在同一个仓库里并行开发，**结构性地避免冲突**，并且协议变更不互相踩。
>
> 最后更新：2026-10-10 · 维护人：桌面侧（协议与服务端归属见 §3）

---

## 0. 三句话 TL;DR

1. **谁改哪些目录**：安卓端只动 `android/**` 和 `docs/android/**`；其余目录归桌面侧（§3）。跨边界先提 Issue 或 PR，不要直接改。
2. **主干只走 PR**：主干是 `codex/tauri2-migration`。自己的分支随便推，**共享分支永不 force-push**。
3. **服务端部署只有桌面侧能做**；keystore / APK **永不入库**（§4.4）。

## 1. 仓库速览

### 1.1 这是什么

ShortCut 是一个面向 Windows 的桌面效率工具（快捷方式面板、任务墙、翻译、驾驶舱、SC 球灵动岛等），
外加一套**移动互联平台**：手机网页与桌面端通过云端中继 / 局域网直连互通（任务同步、文件快传、电脑控制）。

当前正在做 **Electron → Tauri 2 的迁移**，因此仓库里同时存在两套东西：

| 端 | 位置 | 技术栈 | 状态 |
|---|---|---|---|
| 桌面端（当前主线） | `src/`、`src-tauri/` | Tauri 2.12 + React 19 + TS + Vite + Zustand | **在维护，功能以它为准** |
| 桌面端（旧） | `electron/`、`dist-electron/` | Electron 42 | 遗留，逐步退役，别在它上面加新功能 |
| 服务端 | `server/` | PHP（`sync/`）、Node（`control-relay/`）、nginx 配置 | 线上运行中 |
| 移动 Web | `server/sync/web/**` | 原生 JS + 共享 `sdk.js` | 线上运行中（`/mobile/`、`/taskwall/`、`/transfer/`、`/control/`、`/bind/`） |
| **安卓端（新增）** | `android/**` | **原生 Kotlin** | 另一位开发者负责，从零开始 |

## 2. 环境准备

### 2.1 桌面端（Windows）

| 组件 | 版本/位置 |
|---|---|
| Node / npm | Node **24.x**、npm 11.x（仓库根 `npm ci`） |
| Rust | stable toolchain，`%USERPROFILE%\.cargo\bin\cargo.exe` |
| C++ 工具链 | Visual Studio 2022 BuildTools（`vcvars64.bat`，见 §5.2 完整命令） |
| WebView2 | Windows 自带；老版本会导致个别 UI 异常 |
| Tauri | `tauri = 2.12.0`（`src-tauri/Cargo.toml`），构建**不用** `tauri-cli`，直接 cargo（§5.2） |

### 2.2 安卓端

- Android Studio（含 SDK/Platform-Tools）、**JDK 17**
- Gradle Wrapper 随工程提交（务必用 wrapper，别依赖本机 gradle 版本）
- 建议 `minSdk 24+`；注意设备实际 **System WebView 版本**（若用到 WebView 承载站点页面）
- 关键限制见 §8.7 / §8.10（明文 HTTP、稳定设备标识）

### 2.3 服务端

- Linux + 宝塔面板；站点根 `/www/wwwroot/ShortCut`
- PHP **8.2**（站点）/ 本机没有 PHP 7.4 → 服务端语法校验在服务器上跑 `php -l`
- Node 16（仅 relay 服务用），systemd 单元 `shortcut-control-relay.service`
- **服务器凭据不写进仓库**（见 §4.4 红线）

## 3. 工作区归属（避免冲突的核心）

> 冲突几乎总是来自"两个人改了同一个文件"。用目录边界把它结构性消除。

| 目录 / 文件 | 负责人 | 说明 |
|---|---|---|
| `android/**` | **安卓侧** | 原生工程、Gradle、Kotlin 源码、原生资源 |
| `docs/android/**` | **安卓侧** | 安卓设计与踩坑文档 |
| `src/**`、`src-tauri/**` | 桌面侧 | 桌面端渲染层与 Rust 主进程 |
| `electron/**` | 桌面侧 | 遗留，只修 bug |
| `server/**` | 桌面侧 | **服务端 + 移动 Web + 中继**（见下方契约文件清单） |
| `resources/**` | 桌面侧 | 运行时资源与侧车（硬件监控/音乐桥） |
| `tools/**`、`scripts/**` | 桌面侧 | 构建、验证、联调工具 |
| `docs/*.md`（除 `docs/android/`） | 桌面侧 | 协议与设计文档 |
| `README.md`、`HANDOVER.md`、`package.json`、`package-lock.json`、`.gitignore` | 桌面侧（**改前打招呼**） | 这些是小文件但两方都可能想动，最容易冲突 |

### 3.1 契约文件（安卓侧只读，要改必须走 PR）

这些文件定义了安卓端依赖的全部协议，**只有桌面侧能改**：

```
server/sync/api.php          # 所有 action 入口
server/sync/config.php       # 身份/设备/令牌/限流语义
server/sync/file.php         # 文件分片上传下载
server/sync/modules.json     # 模块契约与能力清单
server/sync/web/sdk.js       # 移动 Web 共享 SDK（可当作参考实现读）
server/control-relay/relay.js# 实时中继与消息协议
```

需要新增字段/接口时：**在 Issue 或 PR 里写清 `{action, 入参, 期望返回, 使用时机}`**，由桌面侧实现 + 更新《协议契约》+ 部署，然后通知你。**不要在安卓侧先写死一个假接口**。

### 3.2 桌面侧的反向承诺

桌面侧**不修改 `android/**` 与 `docs/android/**`**（这是双向约定，桌面侧同样受约束）。
如果某个改动必须同时动两端，先在 Issue 里定接口，再各自提交。

## 4. 分支与提交规范

### 4.1 分支

| 类型 | 命名 | 从哪切 | 合到哪 |
|---|---|---|---|
| 功能 | `feature/<scope>-<短描述>` 例：`feature/android-control` | `codex/tauri2-migration` | 主干（走 PR） |
| 修复 | `fix/<scope>-<短描述>` | 主干 | 主干（走 PR） |
| 文档 | `docs/<短描述>` | 主干 | 主干（走 PR） |
| 实验 | `exp/<短描述>` | 主干 | 可以不合并 |

`<scope>` 建议用：`android` / `desktop` / `server` / `mobileweb` / `contract`。

### 4.2 日常循环

```bash
git fetch origin
git rebase origin/codex/tauri2-migration   # 每天开工先同步，冲突早发现
# ... 开发 ...
git add -A && git commit -m "feat(android): 绑定页接入 mobile.bind"
git push origin feature/android-control
# 然后在 Gitee 上开 Pull Request 合到 codex/tauri2-migration
```

规则：

- **只推自己的分支**；主干合并一律走 PR（Gitee「Pull Request」）。
- **共享分支永不 `force-push`**；只对自己的 feature 分支用 `--force-with-lease`。
- 合并前先 rebase 到最新主干，保证历史线性、冲突在小范围解决。
- 一次 PR 只做一件事；别把"顺手重构"塞进功能 PR。

### 4.3 提交信息

```
<type>(<scope>): <中文一句话说清做了什么>

<为什么这么做 / 怎么验证的 / 影响的端>
```

- `type`：`feat` / `fix` / `docs` / `refactor` / `chore` / `perf` / `test`
- 例：`feat(control): 局域网控制一键直连 —— 两边各点一下即连，不用地址、不用绑定码`
- 一个功能一个 commit；不要把无关的格式化/改名混进来（否则 rebase 冲突面爆炸）
- 提交身份请设成自己（否则 `git blame` 混在一起）：
  ```bash
  git config user.name  "你的名字"
  git config user.email "你的邮箱"
  ```

### 4.4 绝对不要提交（红线）

```
android/ 下的：local.properties、*.keystore、*.jks、*.apk、*.aab、build/、.gradle/
通用：node_modules/、dist/、dist-electron/、release/、src-tauri/target/、*.log
任何服务器密码 / 令牌 / 私钥（含截图、文档、脚本里的明文）
```

> **签名 keystore 泄露 = 签名密钥泄露**：轻则别人能签发假冒更新包，重则你再也无法给已安装用户推送更新（签名不一致会被系统拒绝）。keystore 请放在仓库外单独备份，仓库里只记录**指纹（SHA-256）**。

## 5. 构建与验证（桌面侧）

### 5.1 只改前端

```powershell
cd D:\wenjian\js\ShortCut
npx tsc --noEmit        # 类型检查
npm run build           # 产出 dist/（Tauri 会把它嵌进 exe）
```

### 5.2 改 Rust / 出 exe（**必须注意顺序**）

```powershell
# 1) 先关掉正在运行的实例，否则 exe 被占用 → 报"拒绝访问 (os error 5)"
Get-Process shortcut-tauri -ErrorAction SilentlyContinue | Stop-Process -Force

# 2) 前端必须先构建！tauri.conf.json 的 frontendDist=../dist 是【编译期嵌入】，
#    顺序反了会得到一个"健康但界面是上一版"的 exe（踩过，见 docs/tauri-regression.md §15）
npm run build

# 3) 再构建 Rust（约 4 分钟）
cd src-tauri
cmd /c "call ""C:\Program Files (x86)\Microsoft Visual Studio\2022\BuildTools\VC\Auxiliary\Build\vcvars64.bat"" >nul 2>&1 && %USERPROFILE%\.cargo\bin\cargo.exe build --release --features custom-protocol"
```

**自检**（确认 exe 里嵌的是刚构建的前端）：

```powershell
$dist = (Get-ChildItem dist\assets\main-*.js).Name
$ascii = [System.Text.Encoding]::ASCII.GetString([System.IO.File]::ReadAllBytes('src-tauri\target\release\shortcut-tauri.exe'))
$embedded = ([regex]::Matches($ascii,'main-[A-Za-z0-9_\-]{8}\.js') | ForEach-Object Value | Sort-Object -Unique) -join ','
"dist=$dist exe=$embedded 一致=$($embedded -eq $dist)"
```

### 5.3 启动（**必须以普通权限**）

```powershell
powershell -ExecutionPolicy Bypass -File scripts\run-app.ps1
```

该脚本会de-elevate启动并校验 `TokenElevation`。**用管理员权限启动会让外部文件拖放整体失效**（Windows UIPI 限制：禁止光标 + 连拖入事件都不触发），详见 `docs/tauri-regression.md` §15.2。

### 5.4 侧车资源（改到才需要）

```powershell
npm run hardware:build   # 硬件监控 C# 侧车 → resources/hardware-monitor/*.exe
npm run music:bridge     # 音乐桥
```

### 5.5 已知环境限制

- 本机 `cargo test --lib` 在**进程初始化阶段**就失败（`STATUS_ENTRYPOINT_NOT_FOUND`，依赖全是系统 DLL），属既有环境问题 → **验证以行为验证为准**（跑起来看日志/界面/接口）。
- `browser_*` 自动化在本机不可用（缺 Electron 二进制）→ 手机页面用协议级脚本验证。

## 6. 协议变更流程（跨端最重要）

**唯一真源：`docs/移动互联-协议契约.md`。** 安卓端只认它，不认聊天记录、不认代码注释。

变更三步走：

1. **先改文档**：更新契约文档对应章节 + 在 §变更日志 追加一条（日期、变更内容、版本号、兼容性说明）。
2. **再改实现**（桌面侧）：服务端实现 + 部署；**保留旧行为至少一个版本**（本仓库惯例：旧 action 名保留为别名，例如 `push/pull/ack` 兼容 `queue`）。
3. **通知对方**：在 PR 描述与契约 changelog 里写清"安卓端要不要动、怎么动"。

兼容性约定：

- **加分不改语义**：新增可选字段、新增 action、新增返回字段 → 向后兼容，安卓端可以慢慢跟。
- **改语义/删字段/改类型** → 必须提升协议版本号，并在 changelog 标注"破坏性变更"。
- 版本号有三个层次，别混淆：
  - `SYNC_PROTOCOL_VERSION`（`server/sync/config.php`，当前 `1`）：**协议**版本，`module.list` 会回显给客户端。
  - `modules.json` 的 `version`（当前 `1`）：**模块契约**版本（模块清单结构与能力声明的版本）。
  - `minAppVersion`（每个模块）：该模块要求的**客户端版本**下限，客户端据此自己决定是否显示入口。

## 7. 联调与测试

### 7.1 安卓侧怎么测（不需要 Windows 桌面端）

1. **自建测试绑定**（不要拿别人的真实绑定做实验）：
   `POST /sync/api.php` `{action:'bind.create', deviceName:'android-dev'}` → 拿到 `bindId` + `code` + `deskToken`
   之后：任务墙（`push/pull/ack`）、文件分片（`transfer.fileInit` / `file.php`）都能真跑。
2. **实时控制链路**需要中继上有一个 desktop 角色对端：
   - 用 `tools/mock-desktop/`（假桌面桩：以 `role:'desktop'` 连中继并本地回答 `/api/*`）——**若该目录还不存在，找桌面侧要**。
   - 或让桌面侧配合开一次真实桌面端。
3. **联调前先确认协议版本**：`module.list` 返回的 `protocolVersion` 与客户端内置版本是否一致。

### 7.2 常用观测点

| 看什么 | 在哪 |
|---|---|
| 桌面端日志 | `%LOCALAPPDATA%\com.wanan.shortcut\logs\tauri.log`（**时间戳是 UTC，比本地早 8 小时**） |

## 8. 注意事项与踩坑清单

1. **构建顺序**：`npm run build` 必须在 `cargo build` 之前，否则 exe 里是旧前端（§5.2 自检）。用户曾因此报"设备列表看不见"。
2. **别用管理员权限启动 App**：UIPI 会掐掉外部文件拖放（拖到 SC 球/转换面板完全无事件）。用 `scripts/run-app.ps1`。
3. **PowerShell 5.1 编码**：含中文的 `.ps1` **必须带 UTF-8 BOM**；内联命令行里的中文双引号会解析失败。
4. **服务端页面要部署两份**：`/www/wwwroot/ShortCut/<name>/` 与 `/www/wwwroot/ShortCut/sync/web/<name>/` 都在被访问（Cloudflare 前面还缓存静态资源）。
5. **重启 relay 会掐断实时会话**（手机正在控制电脑时会断），非必要别重启；改 `relay.js` 后必须重启才生效。
6. **手机端 `sdk.js` 走 `/sync/sdk.php` 透传**（带 `no-store`），因为 nginx/Cloudflare 会给 `.js` 长缓存；改了 sdk 不要指望静态直连立刻生效。
7. **安卓明文 HTTP**：局域网直连要访问 `http://192.168.x.x:9823`，Android 9+ 默认禁明文 → 必须配 `network_security_config.xml`（放行私网段）或 debug 下 `usesCleartextTraffic`，否则该功能**静默失败**。
8. **`cargo test` 本机跑不起来**（§5.5），别把它当"测试通过"的证据。
9. **桌面端日志时间戳是 UTC**，排查时先 +8 小时。
10. **安卓端必须自己实现"稳定设备标识"**（等价于 Web 的 `shortcut-device-key-v1`：随机生成、长期持久化，别用 `ANDROID_ID`）。不做这件事，每次重绑都会在设备列表里新增一条"我的手机"，很快堆满设备名额——我们修过这个 bug，见 `docs/移动互联设备管理-部署与验收.md`。
11. **不要在真实绑定上做破坏性实验**：`mobile.bind` 会**轮换该设备的令牌**（原凭证立即失效，真机必须重新绑定），`bind.device.remove` 会**吊销设备**。测试请用 §7.1 的自建绑定。（这是实际踩过的坑，写进规范。）
12. **别提交 `docs/references/WinIsland` 之类的子模块脏标记**：那是参考项目，不是我们的代码。
