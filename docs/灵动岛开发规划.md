# ShortCut 灵动岛开发规划

## 1. 文档定位

本文档用于记录 ShortCut 灵动岛功能的需求边界、技术验证项、分阶段交付范围和验收标准。

- 当前状态：需求梳理阶段
- 目标平台：Windows
- 数据原则：继续复用 ShortCut 本地配置与任务数据
- 开发原则：先验证高风险系统能力，再按用户价值逐步交付
- 暂未确认的视觉、天气和交互细节保留为空，不在实现阶段擅自决定

## 2. 产品目标

在 ShortCut 主程序内增加一个可独立开启的桌面灵动岛，以紧凑、置顶的方式聚合以下信息：

1. 网易云音乐播放信息与控制
2. Windows 软件通知
3. 时间与天气
4. ShortCut 待办提醒
5. 系统资源占用

灵动岛随 ShortCut 主程序启动，不增加独立的开机启动项。

## 3. 已确认的整体行为

### 3.1 窗口形态

- 默认位于主屏幕顶部正中。
- 使用独立悬浮窗口并保持置顶。
- 支持改变显示位置。
- 支持切换展示样式，具体样式方案待定。
- 无事件时显示紧凑胶囊。
- 鼠标悬停或有事件时自动展开。
- 无音乐、通知或任务事件时显示时间与天气。
- 允许完全隐藏灵动岛。
- 提供全局快捷键控制显示与隐藏，具体键位待定。
- 可配置全屏应用运行时是否自动隐藏。

### 3.2 设置项

- 灵动岛总开关。
- 音乐模块独立开关。
- 系统通知模块独立开关。
- 时间天气模块独立开关。
- 任务提醒模块独立开关。
- 系统占用模块独立开关。
- 全屏自动隐藏开关。
- 显示位置与展示样式设置，具体控件待设计。
- 灵动岛不创建独立开机启动配置，生命周期跟随 ShortCut。

## 4. 功能需求

### 4.1 网易云音乐

目标数据：

- 专辑封面
- 歌手名
- 歌名
- 当前歌词
- 播放进度与总时长
- 播放或暂停状态

目标控制：

- 上一首
- 播放或暂停
- 下一首
- 拖动进度条跳转

展示规则：

- 收起时显示当前歌词。
- 展开时显示上一句、当前句和下一句歌词。
- 没有媒体播放时退回时间天气状态。

待确认或验证：

- 网易云客户端版本与兼容范围。
- 是否仅支持网易云 Windows 客户端。
- 媒体元数据、控制和进度的读取方式。
- 当前歌词和歌词时间轴的本地解析方式。
- 开源参考项目的许可证、代码结构和可复用范围。
- 是否需要 C# 原生辅助进程。

### 4.2 Windows 系统通知

目标：尽量替代 Windows 通知中心，并尽量隐藏系统原始弹窗，由灵动岛统一展示软件通知。

已确认行为：

- 普通通知到达时临时展开。
- 展示一段时间后自动收起。
- 不保存通知历史。
- 暂不支持快捷回复、通知操作按钮和复杂交互。
- 任务提醒与普通软件通知采用不同持续时间。

必须先验证：

- 当前 Windows 版本可读取的通知范围。
- 获取通知权限的用户授权流程。
- Electron 应用是否需要包身份或额外原生组件。
- 能否可靠避免灵动岛通知与系统原通知重复展示。
- 隐藏系统原始通知对全局系统设置的影响。
- 传统桌面软件、自绘通知和系统级通知的兼容边界。

约束：不得在未经用户确认的情况下永久修改 Windows 全局通知设置。

### 4.3 时间与天气

当前仅作为预定功能，开发优先级靠后。

已确认的紧凑状态内容：

- 当前时间
- 天气图标
- 当前温度

以下内容待开发前确认：

- 天气服务商与 API 密钥
- 城市选择或自动定位
- 刷新频率与缓存策略
- 展开状态信息
- 断网和接口额度耗尽时的降级表现

### 4.4 ShortCut 任务清单联动

已确认范围：

- 仅处理设置了提醒时间的任务。
- 到达提醒时间后灵动岛展开。
- 展示任务标题。
- 点击提醒后跳转到 ShortCut 对应任务墙和任务。
- 不在灵动岛中编辑任务。
- 不支持延后提醒。
- 不支持重复任务。
- 不要求全屏状态下强制显示。
- 提醒保持展示，直到用户点击或处理。

待确认：

- 点击后是否自动关闭提醒。
- 多条任务同时到期时的排序和展示方式。
- 主窗口未显示时，点击提醒如何定位并突出任务条。
- 任务已删除、任务墙已删除时的降级行为。

### 4.5 系统资源占用

当前为后续功能，开发优先级靠后。

已确认范围：

- 用户可以设置灵动岛显示哪些资源数据。
- 默认刷新间隔建议为 2 秒。
- 灵动岛隐藏或对应模块关闭时停止采集。
- 优先复用现有电脑驾驶舱的硬件采集能力，避免重复创建监控进程。

待确认：

- 可选指标清单。
- 紧凑和展开状态的布局。
- 数据异常阈值与提醒规则。
- 是否显示 CPU、GPU、内存、磁盘、网络和电池。

## 5. 状态与事件模型

灵动岛同一时刻需要选择一个主要展示状态。最终优先级待确认，初步事件类别如下：

| 事件类别 | 触发来源 | 是否自动展开 | 结束条件 |
| --- | --- | --- | --- |
| 任务提醒 | ShortCut 任务墙 | 是 | 用户点击或处理 |
| 软件通知 | Windows 通知 | 是 | 超时自动收起 |
| 音乐播放 | 网易云媒体数据 | 播放变化时短暂展开 | 返回紧凑歌词状态 |
| 时间天气 | 本地时间与天气服务 | 否 | 被更高优先级状态替换 |
| 系统占用 | 现有硬件监控服务 | 待定 | 被更高优先级状态替换 |

需要在开发前确定：

- 多个事件同时到达时的展示优先级。
- 普通通知展示时长。
- 音乐切歌后的展开时长。
- 鼠标悬停是否暂停自动收起计时。
- 手动固定展开是否需要支持。

## 6. 技术架构草案

该草案仅用于指导技术验证，不代表最终实现已经确定。

### 6.1 Electron 窗口

- 由主进程管理独立的无边框透明窗口。
- 窗口默认置顶，并支持鼠标交互和点击穿透状态切换。
- 监听显示器变化，防止窗口停留在已断开的屏幕外。
- 保存位置、样式和模块开关到本地配置。
- 主窗口退出时同步销毁，不创建第二个常驻主程序。

### 6.2 原生能力

可能需要扩展现有 C# 辅助程序，统一承载以下 Windows 能力：

- 系统媒体会话读取与控制
- 系统通知读取与权限检测
- 全屏应用检测
- 已有硬件监控数据输出

是否采用一个统一辅助进程，需要在网易云与通知技术验证后决定。必须避免每个模块各自创建长期进程，防止增加内存占用。

### 6.3 前端状态

- 主进程负责原生事件和窗口生命周期。
- 渲染进程负责动画、布局与用户交互。
- 任务数据继续以现有本地 JSON 为唯一数据源。
- 高频媒体进度和硬件数据不写入 JSON。
- 窗口位置、模块开关和展示偏好写入 JSON。

## 7. 开源项目参考流程

用户后续会提供多个同类型开源项目。每个项目按以下格式登记：

| 项目 | 仓库地址 | 许可证 | 参考内容 | 是否复用代码 | 备注 |
| --- | --- | --- | --- | --- | --- |
| 待提供 |  |  | 网易云解析、歌词、样式或交互 | 待评估 |  |

评估规则：

1. 先确认许可证是否允许当前项目使用。
2. 区分直接复用代码、借鉴实现思路和仅参考视觉效果。
3. 优先复用稳定的系统 API，不依赖网易云客户端内部易变结构。
4. 对必须读取本地数据的实现记录兼容版本和失效降级方案。
5. 不把第三方密钥、账号数据或用户隐私写入仓库。

## 8. 技术风险

### 高风险

- 完整替代 Windows 通知中心并隐藏原通知的可行性和权限边界。
- 网易云当前歌词的稳定解析方式。
- 透明置顶窗口在全屏、缩放、多显示器环境下的兼容性。

### 中风险

- 媒体进度拖动控制的客户端兼容性。
- 灵动岛窗口与 ShortCut 全局快捷键、截图功能的冲突。
- 长时间运行后的内存与原生辅助进程占用。

### 低风险

- 时间显示。
- ShortCut 本地任务提醒事件接入。
- 复用现有硬件监控数据。

## 9. 验收基线

每个阶段至少满足以下通用标准：

- 灵动岛关闭时不创建额外长期采集进程。
- 主窗口关闭或隐藏不会导致灵动岛状态异常。
- 不抢占普通输入框的键盘输入。
- 位置在分辨率、缩放或显示器变化后仍可恢复。
- 模块故障不得导致 ShortCut 主程序无法启动。
- 高频数据不持续写入配置文件。
- 新增原生进程必须记录内存占用并支持自动退出。
- 每次实现后同步构建 `release/win-unpacked`，提交并推送源码。

## 10. 开发优先级待定

建议把“技术验证”和“正式交付”分开排序。

### 技术验证候选

- TV-1：网易云媒体数据、控制和歌词解析验证
- TV-2：Windows 通知读取、授权和抑制原通知验证
- TV-3：透明置顶窗口、多显示器和全屏检测验证

### 功能交付候选

- F-1：灵动岛基础窗口、设置总开关、位置保存和隐藏快捷键
- F-2：网易云音乐显示、歌词、播放控制和进度跳转
- F-3：ShortCut 待办提醒与任务墙跳转
- F-4：Windows 软件通知展示
- F-5：时间天气
- F-6：系统资源占用

正式优先级、阶段边界和首个可用版本范围由下一轮讨论确定。
