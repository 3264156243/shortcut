# 安全事件与修复：sync 数据目录曾被公网直接下载（2026-10-08）

> 级别：**严重**（可导致任意绑定被接管 / 电脑被远程控制）
> 发现方式：部署身份层加固后做线上验收时的顺带探测
> 影响范围：`<你的服务器域名>/sync/data/**`（自 2025-09-21 数据目录建立起即存在）
> 状态：**已修复并线上验证**（数据目录移出 web 根 + 备份文件移出 + 泄漏的中继密钥已轮换）

---

## 一、问题清单（均为"修复前实测 200"）

| # | 暴露的 URL | 内容 | 后果 |
|---|---|---|---|
| 1 | `/sync/data/binds.json` | 全部绑定：bindId、**明文 6 位绑定码**、mobile/desk 令牌哈希、设备名 | 拿到绑定码即可 `bind.claimToken` 换桌面凭证 / `mobile.bind` 换移动令牌 → **读写删全部消息与文件** |
| 2 | `/sync/data/control-relay-secret.txt` | **中继 WS 的 HMAC 密钥（明文）** | 可自行伪造任意 bindId 的 `control.ticket` → 直接连中继 → **远程键鼠/剪贴板注入** |
| 3 | `/sync/data/shares.json` | 临时分享：分享码、内容快照、下载令牌 | 用分享码 `transfer.claim` 领取他人分享 |
| 4 | `/sync/data/settings.json`、`rate-limits.json` | 运行设置、限流记录 | 辅助信息泄漏 |
| 5 | `/sync/_bak-api-pre-relay.php` | **旧版（加固前）api.php 的完整副本，且被 PHP 正常执行** | 任何人 POST 该 URL 即绕过全部身份校验（等价于加固从未生效） |
| 6 | `/sync/api.php.bak-*`、`config.php.bak-*`、`file.php.bak-*` | PHP 源码（被当静态文件下载） | 源码/内部路径泄漏，便于找漏洞 |

> 补充：`/sync/config.php` 本身返回空体（正常执行），**没有**源码泄漏。

## 二、已做的修复（全部线上验证）

1. **数据目录移出 web 根**：`/www/wwwroot/ShortCut/sync/data` → `/www/wwwroot/ShortCut-sync-data`
   （站点根 = `/www/wwwroot/ShortCut`，同级目录不在任何 URL 之下）。
   `config.php` 的 `$DATA_DIR` 改为该绝对路径（可用环境变量 `SHORTCUT_SYNC_DATA` 覆盖）；旧目录已移出到
   `/root/sc-backup-20261008/sync-data-old`（保底备份，不再对外）。
   → 复验：`/sync/data/binds.json`、`shares.json`、`settings.json`、`control-relay-secret.txt` 全部 **404**。
2. **备份文件移出 web 根**：`_bak-api-pre-relay.php`、`_bak-config-pre-relay.php`、
   `api.php.bak-*`、`config.php.bak-*`、`file.php.bak-*`、`web/mobile/index.html.bak-*`
   → 全部移到 `/root/sc-backup-20261008/`；web 根内已无备份文件。
3. **nginx 兜底规则**（即使将来文件又被放回 web 根也不可访问）：
   `location ^~ /sync/data/ { return 404; }` 与
   `location ~* ^/sync/.*(_bak-|\.bak|\.old$|\.tmp$|\.part$|\.lock$) { return 404; }`
   （写入 `<你的服务器域名>.conf`，已 `nginx -t` 通过并 reload）。
4. **轮换中继密钥**：`control-relay-secret.txt` 重新生成 48 位 hex（无换行）。
   该文件的消费者有两处，必须同时生效：
   - PHP 侧 `config.php` 读文件（自动生效）；
   - 中继 `control-relay.js` 由 systemd 从**同一文件** cat 出环境变量
     → 已同步更新 `shortcut-control-relay.service` 里的路径并 `daemon-reload && restart`。
   - 复验：relay 进程环境变量与文件指纹一致（`2d4cc3919d`，均 48 位），服务 active、9840 在听。
5. **身份层加固仍有效**：`module.list` 200；`bind.info` 不带凭证不返回绑定码；带错误凭证被拒。

## 三、需要你决定/处理

1. **是否重新绑定**：`binds.json` 与**明文绑定码**在公网可下载约 2.5 周（2025-09-21 起）。
   按"已泄漏"处理最稳妥 —— 在桌面端「设置 → 联动绑定」重新绑定（会生成新 bindId + 新绑定码），手机端重新扫/输入新码。
   不重新绑定的话，风险是：任何当初抓过 `binds.json` 的人，手上仍有你的绑定码。
2. **是否轮换用户组/激活后台**：`server/activation/data/activation_config.json` 是否也能被下载需要单独确认
   （本轮只修了 `sync/` 目录，未逐目录排查整个站点）。
3. **建议加一条例行检查**：站点根下不应出现 `.bak/_bak/.json/.log/.sql` 等文件；数据目录永不放在 web 根内。

## 四、遗留与注意事项（给后续部署）
