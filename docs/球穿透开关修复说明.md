# SC 球「启用穿透」开关失效 —— 根因与修复（2026-10-13）

## 1. 用户报告

「转换设置里的 sc球启用穿透」要挪到 SC 球板块；并且**开关启停没用：显示状态变了，但实际还是可穿透的**。

## 2. 根因（日志实证，不是推测）

应用日志（`%LOCALAPPDATA%\com.wanan.shortcut\logs\tauri.log`）里，用快捷键 Ctrl+Alt+B 反复切换时：

```
[01:38:00] [island] island 鼠标穿透：请求=false 实际可穿透=true ex=0xC0138
[01:38:02] [island] island 鼠标穿透：请求=true  实际可穿透=true ex=0xC0138
[01:38:08] [island] island 鼠标穿透：请求=false 实际可穿透=true ex=0xC0138
```

`ex=0xC0138` 里含 **WS_EX_TRANSPARENT（0x20）**：Windows 侧始终是"穿透"。而**「请求=false」那一行上面没有打印
`[island] 穿透生效 = …`**——说明 `apply_island_and_ball_passthrough_value()` 被缓存提前 return 了，
**根本没去碰窗口样式**。

两个叠加原因：

| # | 位置 | 问题 |
|---|---|---|
| ① | `windows.rs::effective_island_passthrough()`（旧） | 用户开关只在**展开态**有意义：`if 开关 { true } else { displayState != "expanded" }`。收起/迷你态下，开关 ON 与 OFF **算出来的值都是 true**。 |
| ② | `windows.rs::apply_island_and_ball_passthrough_value()` | `PASSTHROUGH_APPLIED` 缓存"值没变就不下发"。①导致值确实没变 → 连样式都不碰 → 从系统层面看**永远穿透**。 |

要命的是默认值：`island.ballClickThrough` 默认 false（开关关），而岛默认是收起态 → **默认就是"恒穿透"**。

## 3. 为什么不能简单地"关掉就不穿透"

岛窗口是**固定 360×340 的透明窗**（`ISLAND_WIDTH/HEIGHT`），收起态的球只占其中一小块。
一旦整窗接收鼠标，球周围那一大圈透明区就会**吞掉桌面点击**——这正是一开始写成
"非展开态一律穿透"的原因。所以正确修法不是"整窗可交互"，而是：

> **不穿透时，只在"可见内容"上可交互；其余区域继续穿透。**

## 4. 修复

### 4.1 穿透判定（`src-tauri/src/windows.rs`）

`effective_island_passthrough(app)` 改为四级：

1. 拖拽进行中 / 拖放菜单打开 → **不穿透**（否则收不到拖放、点不到菜单）——保持原样
2. **用户开关打开（启用穿透）→ 恒定穿透**（连球一起穿透，交给下层窗口）
3. 展开态 → **不穿透**（整窗可交互，原行为不变）
4. 收起 / 迷你态 → **跟随可见内容**：光标在球的矩形内 → 不穿透；移开 → 穿透

第 4 条是本次修复核心：开关终于对"收起态"也有意义了，同时球周围不挡桌面。

### 4.2 "可见内容矩形"从哪来

新增 `ISLAND_HIT_RECT`（逻辑像素，窗口坐标）+ `set_island_hit_rect()`；
岛前端（`src/island.tsx`）在挂载 / 布局变化时把 `.island-root` 的 `getBoundingClientRect()`
经新 IPC `islandHitRect` 上报（ResizeObserver + 1s 兜底轮询 + rAF 去抖，值不变不重复 IPC）。
未上报时默认取整窗（退化为"整窗可交互"，与改动前展开态一致，安全兜底）。

### 4.3 顺带清理

- 删掉死代码 `apply_passthrough(win)`（它用的是不带光标的旧判定，且**从未被调用**——编译警告一直在报它）。
- 拖放守卫的轮询间隔改为**自适应**：只有在"穿透值会随光标变化"时（开关关 **且** 非展开态）才用 40ms，
  其余 120ms。慢了会出现"快速点一下球没反应"。
- 新增日志：`[island] 可见内容矩形 = (x,y,w×h)`，便于现场核对命中框。

## 5. 设置项搬家

| | 之前 | 现在 |
|---|---|---|
| 位置 | 转换板块 → 齿轮设置 → 「SC 球」小节 | **SC 球板块 → 「鼠标穿透」小节**（`IslandPanel.tsx`） |
| 文案 | 「未穿透（收起态仍按岛的显示状态：收起穿透、展开可交互）」 | 明确写清两种状态的实际行为（见下） |

新文案：

- 开启：「整个 SC 球都不接收鼠标，点击直接落到桌面/下层窗口。」
- 关闭：「鼠标移到球上就能点（可拖动、可展开/菜单），移开后球周围不挡桌面点击。」
- 补充：「展开状态下球始终可交互；拖文件到球上时会自动临时解除穿透。」

`ConverterSettings.tsx` 里只留一行注释指向新位置；`SettingsPanel.tsx` 的说明注释同步更新。

## 6. 验证

### 已实测（本机，真实路径，2026-10-13）

**A. 命中框上报**（岛前端 → 主进程）：

```
[island] 可见内容矩形 = (68,10,224×46)
```
即收起态可见胶囊 224×46（而不是整窗 360×340）。**注意第一版量错了元素**：`.island-root` 是
`position:absolute; inset:0` 铺满整窗的容器，量它得到的正好是整窗 → 与默认值相同、等于没生效。
必须量 `.island-shell`（真正的可见/可拖拽内容）。

**B. 光标进/出球 → 穿透值跟随**（轮询实测，DPI=96、岛窗口在 (673,15)，球中心约 (853,48)）：

| 光标位置 | 日志 |
|---|---|
| 移到球上 (853,48) | `穿透生效 = false` ← **球变为可交互**（修复前收起态恒为 true） |
| 移开 (200,700) | `穿透生效 = true` ← 球周围不挡桌面 |

**C. 开关真的落到 Windows**（用 Ctrl+Alt+B，与设置开关同一条 `set_ball_passthrough` 路径，光标保持在球上）：

| | 修复前（01:38 日志） | 修复后（实测） |
|---|---|---|
| `请求=false` | `实际可穿透=true ex=0xC0138`（WS_EX_TRANSPARENT 仍在） | **`实际可穿透=false ex=0x40118`**（0x20 位已清除）✅ |
| `请求=true` | `实际可穿透=true ex=0xC0138` | `实际可穿透=true ex=0xC0138` ✅ |

`ex` 的 0x20 位就是 `WS_EX_TRANSPARENT`——修复前无论请求什么都置位，这正是"显示状态变了但实际仍可穿透"的物证。

**D. 构建自检**：`npx tsc --noEmit` 通过；`npm run build` → `cargo build --release --features custom-protocol` 通过；
内嵌资源自检 `dist == exe`（main 与 island 两套产物都一致）。

### 人工手测（用户）

1. SC 球板块 → 「鼠标穿透」：默认关闭。鼠标移到球上 → 能点/能拖动球；移到球周围空白 → 能点到桌面（不被吞）。
2. 打开开关 → 鼠标移到球上也点不到（点击穿透到桌面）。
3. 展开态 → 无论开关如何球都可交互；打开开关后展开态也穿透。
4. 拖文件到球上 → 仍能识别并弹出转换按钮（拖拽期间自动不穿透）。
5. 快捷键 Ctrl+Alt+B 与设置页勾选状态双向同步。

### 排查小抄

- 日志里所有穿透相关行都在 `%LOCALAPPDATA%\com.wanan.shortcut\logs\tauri.log`：
  `可见内容矩形` / `穿透生效` / `鼠标穿透：请求=… 实际可穿透=… ex=0x…`。
- **grep 这个日志时要带 `-Encoding UTF8`**（PS 5.1 默认按 ANSI 解码，中文会变乱码导致搜不到）。
- 改完前端记得按顺序重建：`npm run build` **先**、`cargo build` 后（否则 exe 里是旧前端）。
