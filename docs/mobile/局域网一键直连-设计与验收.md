# 局域网控制「一键直连」（2026-10-10）

## 1. 要解决的问题

原来的局域网连接要用户做三件事，用户原话是「不要那么多繁琐过程」：

| 繁琐点 | 原实现 |
|---|---|
| ① 手机要知道电脑的地址 | `/control/` 页要用户**手输** `192.168.x.x:9823`（或扫桌面二维码） |
| ② 手机还要输验证码 | 打开局域网控制页后，**再输一次 6 位绑定码** |
| ③ 入口分散 | 手机得先打开 `<你的服务器域名>/mobile` → 电脑控制 → 再选模式 |

而云端连接早就是"自动配对、无需输码"——局域网要对齐的正是这套体验。

## 2. 目标（用户设想）

> 手机端和桌面端都点击局域网控制后，直接跳转到对应页面完成连接

- 桌面端：点「局域网直连」→ 起服务，**就这一步**。
- 手机端：点「局域网控制」→ **直接进入控制界面**，不输地址、不输码。

## 3. 设计

关键前提（侦察得到的事实）：**桌面端到云端中继的 WebSocket 是常驻的**
（`cloud.rs`，与面板上"云端连接"开关解耦）——所以**即使桌面端停在"局域网直连"模式**，
手机端依然能通过云端中继问它一句话。

```
手机(/control/)                      云端中继                       桌面端
   │ ① 控制票据(control.ticket role=mobile)
   ├──────────────────────────────────────────────► api.php
   │ ② WS 首帧 {auth:{role:'mobile',ticket}}
   ├───────────────────► relay.js ─────────────────► 桌面常驻连接
   │ ③ {t:'api', path:'/api/lan-entry'}
   ├───────────────────► 转发 ─────────────────────► cloud.rs::handle_api
   │                                                   └─ 回 {running,url,urls,token,pairCode}
   │ ④ 拿到 url + 预授权令牌
   └─ location.href = url + '/?token=<48hex>'  ─────► 局域网控制页（resources/sj/）
                                                        └─ 已有 ?token= 注入：直接进控制界面
```

要点：

1. **不新增服务端存储**：没有 TTL、没有心跳上报——入口是**现问现答**的，永远是最新的
   （桌面端没起服务就答 `running:false`，手机端据此给中文提示，而不是白屏）。
2. **预授权令牌**：桌面端启动局域网服务时生成一个 48 位 hex 令牌并**直接插进会话表**
   （`sessions`），等价于"已经输过绑定码"。手机带 `?token=` 打开即可，**局域网页一行都没改**
   （它本来就支持 `?token=` 注入）。停止服务 → 随 `ControlState` 一起失效。
3. **二维码同源受益**：桌面端二维码/状态卡里的 URL 现在**自带令牌**，扫码也是直接进
   （原来扫码后还要手输绑定码）。
4. **中继白名单**：`relay.js` 的 `ALLOWED` 增加 `/api/lan-entry`（原来只放行注入类指令）。
5. **备用路径保留**：手填地址 + 6 位绑定码仍然可用（手机没网、拿不到入口时兜底），
   只是从"主路径"降级为"备用"，界面文案同步改掉。

| 文件 | 内容 |
|---|---|
| `src-tauri/src/control.rs` | `LAN_ENTRY` 进程内单例（`set_lan_entry` / `lan_entry`）、`new_token()`；`api_pair` 改用 `new_token()` |

| `server/sync/web/sdk.js` | 新增 `sdk.requestDesktop(path, body)`：换票 → 一次 WS → 鉴权 → 一问一答 → 关闭（通用原语，后续板块可复用） |

| `src/components/ControlPanel.tsx` | 二维码/URL 带令牌；文案改为"手机点一下即连，不用地址不用码"；绑定码降级为「备用连接码」 |

- **部署**：`relay.js` / `sdk.js` / `control/index.html` 已上线（备份 `_bak-lan-20261010-202237`），
  relay 服务重启后 `active`，`/healthz` 正常。
- **语法**：`node --check` 通过（sdk.js / relay.js / 页面内联脚本）。
- **链路（真实协议，用 node+ws 按 `requestDesktop` 的步骤走）**：
  `control.ticket` → 中继 WS 鉴权 `desktopOnline=true` → 发 `/api/lan-entry` →
  **桌面端答复 `ok=true status=200 data={"running":false}`**。
  即：中继白名单、移动端票据、常驻连接、`cloud.rs` 新分支、回程路由**全部打通**；
  `running:false` 正是手机端"电脑端还没开启局域网直连"提示分支。
- **Rust 构建**：`cargo build --release --features custom-protocol` 通过，内嵌前端自检一致。

### 待人工手测（需要真实点击/真实手机）

1. 桌面端「控制」板块点 **局域网直连** → 状态卡出现地址与二维码。
2. 手机打开 `<你的服务器域名>` → 「电脑控制」→ 点 **局域网控制** → 应**直接进入控制界面**

   「电脑端还没开启「局域网直连」…」而不是白屏或转圈。

### 环境限制（记录，避免误判）

- 本机 `cargo test --lib` 在**进程初始化阶段**就崩（`STATUS_ENTRYPOINT_NOT_FOUND`，
  依赖全是系统 DLL），属既有环境问题，与本轮改动无关 → 本轮验证以行为验证为准。
- 本机浏览器自动化（`browser_*`）不可用（缺 Electron 二进制），故手机页面用
  协议级脚本 + 语法检查替代真机。
- 桌面端「局域网直连」只能由界面点击触发（无命令行入口），所以第 5.2 节必须人工点一次。

## 6. 安全边界与取舍

- 入口令牌 = **预授权会话**，随桌面端停止服务即失效；48 hex 强于原 6 位绑定码。
- 它只经**移动端票据鉴权的云端中继**下发；局域网 HTTP 服务**不**暴露该接口
  （避免同网段任何人直接问走令牌）。
- 已知取舍：拿到二维码/URL 的人（同网段）即可控制电脑——与"扫码即连"的体验是同一次取舍，
  用户已明确接受（测试环境）。要收紧可后续给令牌加"设备绑定/IP 白名单/一次性"。
- 同网段判断未做（服务端没有桌面端公网 IP 的可靠记录）：手机若与电脑不同网络，
  由用户看到浏览器错误后回退云端；界面文案已写明这个前提。

## 7. 回滚

1. 服务端：恢复 `_bak-lan-*` 目录里的 `relay.js` / `sdk.js` / `control/index.html`，
   `systemctl restart shortcut-control-relay`。
2. 客户端：`git revert` 本轮提交（`cloud.rs` 的 `/api/lan-entry` 分支、
   `ControlPanel.tsx` 文案与二维码、`control/index.html` 按钮）。
   回滚后局域网回到"手输地址 + 输绑定码"的老流程，功能不会中断。
