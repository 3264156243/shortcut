# 文件快传链路复核（2026-10-23）

范围：Tauri 桌面端、移动网页、线上 PHP 文件接口，对照《文件快传与通用移动联动开发计划》《文件快传审计问题清单》《移动互联-协议契约》。先完成链路复核，再按数据安全、桌面闭环、轮询体验的顺序实施修复；测试使用隔离数据目录，不读取或修改正式绑定与传输记录。

## 结论与验证边界

基础云端协议闭环可用，本轮发现的上传生命周期、完成校验、共享领取、桌面落盘和轮询问题已完成修复。尚未完成真实手机与正式发布版桌面程序的公网端到端验收，续传队列和局域网直传仍属于后续能力。

- 线上 `api.php/config.php/file.php/sdk.js` 与仓库 SHA-256 一致；线上 transfer/bind 页面与仓库忽略 CRLF 后一致。
- 本机配置中的绑定仍存在，桌面凭证哈希与服务器匹配，该绑定登记了 3 台移动设备。只比较身份摘要，未输出凭证或读取消息正文。
- 线上页面可访问；PHP 上传限制 50MB、Nginx 请求体限制 50MB，不构成当前 2MB 分片的静态限制。
- 最近 6000 条访问日志中有 API 与 transfer 页面访问，未见 file.php 请求；这只是有限日志窗口，不能证明此前从未传过文件。HTTP 200 也不能代替 JSON success 验证。
- 在服务器 `/tmp/sc-transfer-audit-*` 独立目录复制线上接口，使用 PHP 8.2 本地回环监听、全新数据目录及测试身份。结束后关闭进程并删除该临时目录，正式用户数据未参与测试。
- 修复前隔离测试通过基础协议；修复后再次通过：桌面与移动双向多分片文件、下载字节与 SHA-256 一致、完成接口幂等、两个领取者获得互不覆盖的下载令牌、错误分片大小拒绝、文件/共享时长策略限制、活跃上传清理保护及过期消息清理。
- 上述测试覆盖接口协议，不覆盖公网/CDN 上传路径、真实移动系统下载行为、Tauri 文件对话框及实际落盘，因此不能写成“真机双向传输已验收”。

## 复核时发现的问题

| 优先级 | 问题与实际后果 | 当前证据 |
|---|---|---|
| P0 | 定期清理将正在上传的文件当孤立文件立即删除。消息直到 complete 才创建，但清理以“是否被消息引用”作为删除条件，没有上传状态或宽限期。轮询等 API 请求跨过 15 分钟清理点即可触发，短上传也可能碰上。 | `server/sync/config.php:1209`、`:1287`；隔离复现：刚初始化的上传会话被清理，元数据消失。 |
| P1 | 桌面端领取文件共享后无下载动作。claim 只读取 `message.text`，忽略 `downloadToken` 和文件消息，再清空输入框。桌面端创建共享也只有文本入口。 | `src/components/FileTransferPanel.tsx:97`、`:110`；`src-tauri/src/transfer.rs:229`。 |
| P1 | 过期消息清理拼成 `xxx.json.json`。遍历目录得到的文件名已经带 `.json`，再次拼后缀导致跳过真实文件。文件按期删除、消息仍留下，会产生“看得到却下载不了”的条目。 | `server/sync/config.php:1249`；隔离复现：48 小时前的非收藏消息，在 24 小时清理后仍存在。 |

| P1 | 桌面上传一次读入整个文件，再按分片切片。大文件占用等量内存，读取期间文件截断还可能令后续切片越界。 | `src-tauri/src/transfer.rs:66-101`。 |

## 本轮实施结果

- 服务端为未完成上传保留 24 小时活动窗口，修正消息清理路径；分片写入状态改为带锁更新，并按每片应有字节数拒绝残缺数据。
- 完成上传时重新核对全部分片和实际总大小、计算 SHA-256，并在同一文件级锁内保证重复请求只产生一条消息。
- 文件共享改为每次领取签发独立令牌，下载完成后才消费；增加领取频率限制，并把单文件大小、云空间、共享开关和最长时长策略落实到接口。
- 桌面端上传改为固定缓冲区流式读取；下载边接收边计算 SHA-256，保留中文名，自动处理重名，使用配置中的下载目录，并在目标盘内写临时文件后落盘。
- 桌面端补齐文件消息创建共享、公开接收密码领取文件和下载落盘；移动页允许未绑定访客领取共享。
- 桌面和移动轮询均防止请求重叠；桌面不再每次轮询闪烁加载或重复报错，移动页保留用户阅读位置、显示读取错误，并在页面恢复时继续轮询。
- 前端生产构建、Rust `cargo check`、移动页内嵌脚本语法检查均通过。PHP 8.2 隔离链路测试覆盖双向 3 分片传输、哈希一致、完成幂等、两人并发领取、错误分片、策略边界和清理边界。
- 服务端已在 2026-10-23 安全部署；替换前备份位于 `/www/backup/shortcut-transfer-fix-20261023-171817`。线上接口与本地文件哈希一致，公开 transfer 页面已确认返回新版本。

后续实现已补齐：确定性恢复键、上传缺片恢复、Range 下载恢复、桌面与移动多文件队列、取消/重试、实时速度与预计时间、图片粘贴与预览、收藏、下载目录、自动复制、本地历史，以及 SC 球三个独立开关。真实 WebRTC/DataChannel 局域网直传、后台用户用量看板、正式发布版与真机公网验收仍未完成。

## 与旧文档的差异

- 旧 S1 的下载令牌分支顺序问题已修复，不能继续判为文件共享下载必然失败。
- 旧 S2/S3 的身份加固已进入当前实现；隔离测试无凭证不能读已签发凭证的绑定。未据此扩大声明为全面安全审计通过。
- 桌面 chunkCount 校验、参数编码、绑定缓存和真实错误分类已有改动，旧 D4/D6/D8/D9 不应照抄为完全未修。
- `blob.status` 已实现，文档中“缺片查询全无”的说法过时；真正缺的是两端消费它形成续传闭环。
- 文件名中文丢失、上传会话被清理、消息清理路径错误、重复 complete 是本轮明确补充的问题。
- WebRTC/DataChannel 局域网直传与断线云接力仍未发现实现；现有文件链路是云端分片。
- 进度/速度/预计时间、传输队列、桌面多选/拖拽/粘贴图片、图片缩略图、收藏、下载设置、本地传输历史、SC 球快传集成仍未达到计划要求。`fileTransfer` 配置类型声明不能当成已接线功能。
