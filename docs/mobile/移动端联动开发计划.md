# 移动端联动 · 任务墙云同步 开发计划书

> 版本：v1.0
> 状态：待评审
> 关联板块：任务墙（第一个接入云同步通道的板块）
> 目标版本：V2.4.5

---

## 1. 背景与目标

ShortCut 桌面端将逐步支持移动端联动。**第一期**实现任务墙联动：

- 手机浏览器打开 Web 页 → 提交任务（标题/详情/提醒时间/目标墙）
- 任务**暂存云端**
- 桌面端**启动时自动拉取**，加入任务墙，并弹系统通知
- Web 页视觉风格与桌面端任务墙保持一致

**底层原则**：不是做"任务墙专用接口"，而是建设一个**通用云同步通道**（服务端 `sync` API + 客户端同步引擎），任务墙是第一个接入板块。后续语音、剪贴板、笔记等联动板块直接复用同一通道。

## 3. 总体架构

```
┌──────────────┐        ┌───────────────────────┐        ┌─────────────────┐
│  手机浏览器    │  HTTPS │  云端 (43.108.21.35)    │  HTTPS │  ShortCut 桌面端  │
│  /taskwall/  │ ─────► │  /sync/api.php         │ ─────► │  同步引擎         │
│  提交任务      │        │  JSON 存储 + flock 锁   │        │  启动时拉取        │
└──────────────┘        └───────────────────────┘        └─────────────────┘
        │                        │  ▲                           │
        │ 绑定码/扫码              │  │ 提交(绑定身份)              │ 加入任务墙+通知
        ▼                        ▼  │                           ▼
   ┌─────────────┐        ┌─────────────────┐        ┌─────────────────┐
   │ 绑定管理(通用)│        │ 待推送队列(按绑定) │        │ 任务墙板块          │
   └─────────────┘        └─────────────────┘        └─────────────────┘
```

**核心设计——通用云同步通道**：

- **服务端**：`/sync/api.php` 单一入口，`action + board` 分发。`board=taskwall` 表示任务墙联动；后续 `board=clipboard`、`board=voice` 等复用同一入口、同一绑定身份、同一队列机制。
- **客户端**：`sync-engine`（主进程模块）统一处理：绑定身份管理、拉取、上报、错误重试；各板块提供自己的"消费回调"。
- **绑定身份**：一个桌面端 = 一个绑定标识（`bindId`），永久固定，生成后可随时在设置中查看（绑定码 + 二维码）。所有联动板块共用同一绑定标识。

## 4. 服务端设计（PHP）

### 4.1 目录结构

```
server/sync/
├── api.php          # 统一同步入口（action + board 分发）
├── config.php       # 配置、存储路径、绑定数据读写、flock 封装
└── data/
    ├── binds.json           # 绑定标识 → 设备信息（生成绑定码）
    └── queues/
        └── taskwall/
            └── {bindId}.json   # 该绑定下的待推送任务队列
```

### 4.2 API 设计（`/sync/api.php`）

统一请求格式：`POST { action, board, bindId, payload }`

| action | board | 说明 |
|--------|-------|------|
| `bind.create` | `system` | 桌面端申请绑定标识 → 返回 `bindId` + 绑定码 + 二维码内容（`bindId` 编码） |
| `bind.query` | `system` | 绑定码 → 查询绑定是否有效（手机 Web 输入绑定码时调用） |
| `bind.resolve` | `system` | 绑定码 → 解析为 `bindId`（手机提交前校验） |
| `push` | `taskwall` | 手机提交任务入队（需有效绑定身份） |
| `pull` | `taskwall` | 桌面端拉取队列（返回全部未消费任务，暂不删除） |
| `ack` | `taskwall` | 桌面端成功写入后确认消费，服务端按任务 ID 删除 |
| `board.list` | `taskwall` | （可选）返回该绑定下已有墙名列表，供手机选墙 |

**安全**：
- `bindId` 为高熵随机串（如 24 位 base62），绑定码为 6 位短码（映射到 bindId，短码仅用于手机输入，扫码直接用 bindId 编码）。
- `push` 需携带有效 `bindId`（校验存在）。
- 简易限流：同一 IP 提交频率限制（如 1 秒 1 次），防刷。

### 4.3 存储与并发

- 队列存储：`queues/taskwall/{bindId}.json`，结构：
  ```json
  [ { "id", "text", "details", "reminderAt", "boardName", "createdAt" } ]
  ```
- **并发安全**：所有读写通过封装函数 `with_lock($file, $fn)` 使用 `flock(LOCK_EX)` 串行化，多手机同时提交/桌面拉取不会损坏数据。
- 数据保留策略：拉取即从队列移除；`binds.json` 永久保留（绑定固定永久生效）。

## 5. 客户端设计（Electron）

### 5.1 通用绑定模块（可复用）

新增 `electron/sync/binding.ts`：

- `getOrCreateBind()`：首次调用向云端 `bind.create` 申请，返回并持久化 `bindId`（存 `config.json → sync.bindId`）；之后固定复用。
- `getBindCode()`：本地缓存绑定码（云端生成 6 位短码，映射 bindId）。
- `getBindQrContent()`：返回二维码编码内容（bindId 直链，如 `https://shortcut.326415.xyz/taskwall/?bind={bindId}`）。
- 设置面板「联动绑定」卡片：展示绑定码 + 二维码 + 复制按钮 + 说明。

### 5.2 同步引擎（可复用）

新增 `electron/sync/engine.ts`：

- `pullBoard(board)`：调用 `sync.pull`，把云端任务交给该板块注册的消费回调。
- 统一错误处理、超时、失败重试（下次启动再拉）。
- 注册机制：`syncEngine.registerConsumer('taskwall', consumerFn)`——任务墙是第一个注册者，后续板块各自注册。

### 5.3 任务墙接入

- **启动拉取**：应用启动（`ready` 后、任务墙初始化时）调用 `pullBoard('taskwall')`。
- **消费回调**：收到云端任务列表后，逐条调用 store 的 `addTask`（或新增 `addRemoteTask(boardName, task)`）：
  - `boardName` 匹配现有墙 → 加入该墙；不存在 → 自动新建该墙并加入。
  - 任务字段映射：`text`→标题、`details`→详情、`reminderAt`→提醒时间；`x/y/rotation/tape/zIndex` 由 `addTask` 现有逻辑随机生成。
- **系统通知**：拉取到 N 条后，`new Notification({ title: '收到手机任务', body: '收到 N 条任务，已加入任务墙' })`，仅提示不跳转。
- **新增 IPC**：`sync:getBinding`（设置面板展示）、`sync:pullNow`（可选手动拉取按钮）。

### 5.4 配置

`config.json → sync`：
```json
{ "sync": { "bindId": "..." } }
```

## 6. Web 端设计（`server/sync/web/` 或 `website/taskwall/`）

- 地址：`https://shortcut.326415.xyz/taskwall/`（独立响应式页面，纯前端 HTML/CSS/JS + fetch 调 `/sync/api.php`）。
- 流程：
  1. 首页：输入 6 位绑定码（或通过 `?bind={bindId}` 扫码直链进入，自动跳过输入）→ 校验绑定有效。
  2. 提交页：标题（必填）、详情（可选多行）、提醒时间（可选 datetime-local）、目标墙（可选，输入墙名；留空默认墙）。
  3. 提交成功 → 成功动画/文案 → 可继续提交。
- **视觉风格**：复刻任务墙——便签纸质感（暖色卡片、圆角、轻微旋转、顶部胶带装饰）、与桌面端一致的配色（`#c0392b/#e67e22/...` 胶带色、米黄便签底）。
- 移动端适配：viewport、大按钮、触控友好。

## 7. 数据流示例

```
[手机] 打开 /taskwall/?bind=xxx → 填标题"买牛奶"、墙名"生活" → POST sync.push
  → 服务端校验 bindId → 入队 queues/taskwall/{bindId}.json（flock 写入）

[桌面] 下次启动 → syncEngine.pullBoard('taskwall')
  → 服务端返回队列并清空 → 消费回调:
      "生活"墙不存在 → 新建 → 加入"买牛奶"任务（含提醒时间）
  → Notification("收到 1 条手机任务，已加入任务墙")
```

## 10. 风险与注意事项

- **服务器 SSH 部署**：需使用 `D:\wenjian\mima\服务器连接信息.md` 中的密码，通过 Posh-SSH 上传。
- **JSON 并发**：必须统一走 flock 封装，任何绕过封装直接写文件的操作都要避免。
- **绑定码碰撞**：6 位码需保证唯一（生成时查重）；绑定量极低，碰撞概率可接受。
- **提醒时间时区**：手机提交用本地时间 → 传 ISO 带时区 → 桌面端展示本地时间，注意转换一致性。
- **离线桌面**：桌面端长期不启动，云端队列按绑定累积（容量上限需设，如每绑定最多 500 条防滥用）。
- **权限管理**：`taskwall` 联动是否需要纳入激活权限体系（复用模块权限）待定——建议默认跟随「任务墙」板块权限，不单独设限。
