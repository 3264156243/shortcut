# ShortCut 文件快传与通用移动联动开发计划

> 文档版本：1.0  
> 状态：需求已确认，进入开发  
> 目标版本：V2.4.5 及后续迭代  
> 关联模块：通用移动绑定、文件快传、SC球、激活授权后台

## 1. 项目背景

ShortCut 的移动端能力不是任务墙的附属页面，而是一套可持续扩展的移动联动平台。现有任务墙同步是第一项能力，本期新增“文件快传”常用板块，并将绑定身份、移动首页、消息协议和权限策略设计为后续剪贴板、语音、遥控及安卓封装都可复用的基础设施。

## 2. 总体目标

- 建立一个移动端与桌面端严格一对一的通用绑定关系。
- 新建统一移动 Web 首页，绑定后进入功能导航，任务墙与文件快传作为首批入口。
- 文件快传采用聊天式界面，双向发送纯文本、单文件、多文件和剪贴板图片。
- 同一局域网优先使用 WebRTC 点对点传输；失败时按相同分片进度自动切换到云服务器中转。
- 支持分片上传、断点续传、进度、速度、预计时间、取消、重试和本地传输历史。
- 支持临时共享：生成 6 位接收密码，发送者可修改；其他客户端输入密码领取文本或文件。
- 文件快传接入板块管理、用户组权限、服务器配额和 SC球。
- 保持对当前配置文件和既有任务墙同步数据的向后兼容。

## 3. 明确不做

- 不做共享房间、房间成员或多人聊天室。
- 第一阶段不发送整个文件夹；文件夹后续可通过自动压缩方案扩展。
- 不在本期制作安卓安装包，但移动 Web 的路由、身份、API 和文件能力必须适合后续 WebView/Capacitor 封装。
- 不自动下载点对点收到的文件；文件先进入聊天记录，由用户点击或拖拽下载。
- 不限制领取次数；共享内容只受有效期和权限控制。

## 4. 用户与使用场景

### 4.1 点对点快传

- 一个移动端严格绑定一台电脑。
- 新手机完成绑定后，旧移动端身份立即失效。
- 移动设备首次绑定自动生成名称并允许用户修改。
- 双方在聊天式时间流中发送文本、文件和图片。

### 4.2 临时密码分享

- 用户选择文本、图片或文件后进入“共享发送”。
- 系统自动生成 6 位接收密码，用户可以修改为自己的 6 位密码。
- 用户选择分享有效期，不能超过其用户组允许的最大时长，平台上限为 24 小时。
- 桌面 ShortCut、移动 Web 及未来安卓客户端都能输入接收密码领取。
- 领取文本后提供复制，并遵循“收到文本自动复制”设置；领取文件后显示在聊天/领取记录中，由用户下载。

### 4.3 离线与跨网络

- 对端离线时，消息和文件进入云端中转。
- 对端恢复在线后继续拉取消息和未完成分片。
- 未收藏内容按管理后台统一保留时间清理，默认 24 小时。

## 5. 功能需求

### 5.1 通用移动端身份

- 沿用现有 `bindId + 6 位绑定码 + 二维码`，升级为平台公共绑定身份。
- 移动端首次绑定生成独立移动设备令牌，不再直接长期使用裸 `bindId`。
- 服务端只允许一个当前有效移动设备；重新绑定会轮换令牌并使旧设备失效。
- 二维码、扫码绑定和手动绑定码均进入统一移动首页。
- 桌面设置中可以查看当前移动设备名称、绑定时间并主动解除绑定。

### 5.2 统一移动首页

- 地址规划为 `/mobile/`，绑定成功后展示功能导航。
- 首批功能：任务墙、文件快传；输入接收密码属于文件快传页内部能力，不放在移动首页或框架外。
- 原 `/taskwall/` 保留兼容入口，未绑定时跳转或复用统一绑定流程，已绑定时进入任务墙。
- 页面使用可安装式移动 Web 架构，避免依赖桌面专有能力。

### 5.3 文件快传聊天界面

- 桌面端和移动端使用同一消息时间流。
- 消息类型：`text`、`file`、`image`。
- 文本消息提供复制按钮；桌面设置可开启收到文本自动复制到剪贴板。
- 文件/图片显示名称、大小、发送方向、时间、状态和下载入口。
- 图片可显示缩略预览，但原图仍按文件下载。
- 输入区支持文本输入，右侧加号选择一个或多个文件。
- 桌面端支持拖拽文件到聊天区发送，以及粘贴文本、图片或文件发送。
- 删除消息需要二次确认；删除后所有端同步消失，并删除对应云端文件和分片。
- 收藏消息后永久保留，受用户组云端空间配额限制；取消收藏后重新进入普通清理策略。

### 5.4 下载与本地文件

- 首次使用文件快传时询问：使用默认下载目录或自定义目录。
- 默认目录为系统下载目录下的 `ShortCut 快传`。
- 设置中可以随时修改下载目录。
- 点击文件下载到所选目录。
- 从聊天记录向资源管理器拖出文件时，下载到当前拖放目标；受 Electron/Windows 拖出能力限制时，降级为下载后打开所在目录。
- 文件不会因收到消息而自动下载。

### 5.5 传输状态

- 每个传输任务显示进度、实时速度、预计剩余时间和当前通道。
- 支持取消、失败重试和中断后继续。
- 多文件作为多个独立消息进入统一传输队列。
- 本地保存传输历史，包括方向、文件名、时间、结果、通道和本地路径；用户可删除历史记录。

### 5.6 局域网优先与云端兜底

- 第一版必须同时具备 WebRTC 局域网直传和云端中转。
- 服务端承担设备在线状态、WebRTC 信令、传输会话和分片状态协调。
- 点对点双方在线时尝试 WebRTC DataChannel。
- WebRTC 建连超时、网络切换或通道中断后，自动从已确认分片进度切换到云端中转。
- 两种通道使用同一分片编号、哈希和完成确认协议，避免重新传完整文件。
- 对端离线时直接走云端，不等待 WebRTC。

### 5.7 分片与断点续传

- 上传和下载均支持断点续传。
- 每个文件使用随机文件令牌和传输会话 ID。
- 分片必须校验大小和哈希；服务端完成全部分片后原子合并。
- 客户端恢复时先查询已确认分片，只传缺失部分。
- 文件完成后保存完整文件哈希，用于下载完整性校验。

### 5.8 SC球集成

在 SC球设置面板新增“文件快传”独立区域，提供三个互不依赖的开关：

1. 新文本/文件短暂提醒。
2. 上传和下载进度显示。
3. 将文本或文件拖到 SC球后自动发送给已绑定移动端。

- 未绑定移动端时，拖入 SC球必须提示先绑定，不得静默上传。
- 提醒可点击跳转到文件快传板块。
- 音乐播放等更高优先级内容出现时，文件传输信息按现有 SC球内容优先级协调，不破坏音乐球固定尺寸。

## 6. 权限与管理后台

### 6.1 板块权限

- 新增独立模块 ID：`fileTransfer`，名称“文件快传”。
- 客户端模块上报后自动加入激活管理后台用户组策略。
- 文件快传默认位于左侧常用区，排在翻译后；用户可在板块管理中调整位置、顺序或禁用。
- 禁用后停止文件同步轮询、WebRTC、上传下载队列和 SC球文件快传服务。

### 6.2 用户组策略

每个用户组增加：

- 是否允许使用文件快传。
- 单文件最大大小。
- 云端同时占用空间上限，包含未过期文件和已收藏文件。
- 是否允许临时密码分享。
- 临时分享最大有效时长，不能超过 24 小时。

### 6.3 平台全局策略

- 普通未收藏消息默认保留 24 小时，管理员可在 Web 后台修改。
- 服务端定时清理过期消息、文件、孤立分片和失效会话。
- 收藏内容不按普通保留时间删除，但始终受所属用户组空间配额约束。

## 7. 安全要求

- 所有上传、下载、消息、收藏和删除操作必须校验绑定身份或有效接收密码。
- 文件下载使用不可猜测的随机令牌，不能暴露真实磁盘路径。
- 接收密码为 6 位字母数字组合；自定义密码必须检查占用冲突和格式。
- 严格限制文件名，禁止目录穿越和覆盖服务端任意文件。
- 上传必须校验声明大小、分片大小、分片序号、配额和最终哈希。
- API 使用限流、防重放会话标识和明确的过期时间。
- 服务端不执行、解压或预览可执行文件；下载响应使用附件模式和安全 MIME 处理。

## 9. 技术架构

### 9.1 服务端

- 继续使用现有 Nginx + PHP 站点。
- 元数据第一期沿用 JSON + 独立锁文件 + 原子替换，但按绑定、文件和分享拆分目录，避免单一大 JSON。
- 文件内容使用独立上传目录和分片目录，不写入 JSON。
- Nginx/PHP 配置支持分片请求，不依赖单次超大 POST。
- 增加清理脚本和定时任务。
- WebRTC 使用轻量信令接口；若 HTTP 轮询无法满足实时建连，再增加独立 WebSocket 信令服务。

### 9.2 Electron 桌面端

- 新增 `electron/file-transfer/`，负责会话、分片、下载、WebRTC、恢复和通知。
- 渲染层新增 `FileTransferPanel`，只负责聊天 UI 和用户操作。
- 配置保存下载目录、自动复制文本、SC球开关和本地传输历史。
- 传输服务只在 `fileTransfer` 板块启用且授权允许时运行。

### 9.3 移动 Web

- 新增统一 `/mobile/` 应用外壳和路由。
- 身份令牌保存到浏览器安全存储可用范围内；未来安卓壳迁移到系统安全存储。
- 文件选择、分片、哈希和 WebRTC 在浏览器端完成。
- 保留降级能力：不支持 WebRTC 时直接使用云端中转。

## 10. 配置兼容

- 现有 `config.json → sync.bindId/bindCode/bindUrl` 保留并迁移到扩展结构，不删除旧字段。
- 新增配置必须提供默认值，旧版用户升级后不丢快捷方式、任务墙、SC球或其他设置。
- 文件传输历史与主配置分文件保存，避免频繁写大配置。
- 配置仍按现有策略保留三份本地备份。

## 12. 验收标准

1. 同一绑定只能存在一个有效移动设备，新绑定会使旧设备失效。
2. 桌面和移动端能双向发送文本、单文件、多文件和粘贴图片。
3. 对端离线时消息与文件可靠暂存，恢复在线后可继续。
4. 上传和下载均可从已确认分片恢复，不重新传完整文件。
5. 同局域网时优先 WebRTC，失败后自动切换云端且保留进度。
6. 500 MB 文件在移动网络中断后能够恢复并通过完整哈希校验。
7. 临时分享密码可自动生成和自定义，所有客户端均可领取，有效期不超过用户组权限。
8. 收藏受云空间配额控制，删除在所有端同步并清除云端文件。
9. 板块禁用后相关后台服务、轮询、WebRTC 和 SC球能力停止。
10. 旧配置升级后所有原有快捷方式、任务墙及设置保持完整。

## 13. 开发约束

- 不对现有 Electron/React 主架构进行大规模重写。
- 优先复用现有同步绑定、模块管理、授权后台、SC球和配置备份机制。
- 文件内容不能进入主配置或 Git。
- 服务器写入必须使用锁和原子操作，禁止直接覆盖共享 JSON。
- 开发中出现本文档未覆盖的协议、权限、交互或数据边界时，直接向用户提问，不自行决定。
