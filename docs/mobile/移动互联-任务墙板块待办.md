## 一、实测问题

### T1【Bug】手机显示"已绑定但只看得到默认任务墙"，且推送的任务桌面"收到了却没出现在墙上"

用户描述：
- 手机 Web `/taskwall/` 已绑定成功，但**墙列表只有"默认任务墙"**；
- 发送 1 条测试任务，**桌面提示/日志显示接收到 1 条，但任务墙上实际没有这条**。

已核实的链路事实（读代码得到，非推测）：
- 手机墙列表来自 `POST api.php {action:'board.list', board:'taskwall', bindId}`，服务端直接返回
  `binds[bindId]['boards']`——**这个列表是桌面端上报的**（`bind.boards.update`），
  桌面侧来源是 `sync.rs::read_board_names()` → `config.taskBoards[].name`。
  → 桌面**没上报过 / 上报失败 / 上报内容为空**时，手机端就只能拿到空列表并落到"默认任务墙"。
- 桌面接收后写入的是 `config.taskBoards[].notes[]`（`sync.rs::pull_taskwall`）：
  按 `task['boardName']` 找同名墙，**找不到就新建一面墙**（id `sync_<hex>`），把便签塞进去。
  → 手机发的 `boardName` 与桌面已有墙名不一致（或为空 → 落到"默认任务墙"）时，
  任务会进入**新建成的那面墙**，而 `activeTaskBoardId` 并没有切过去
  （任务墙 UI 只渲染 `activeTaskBoardId` 对应的那面墙，见 `src/components/TaskBoard.tsx:82-83`），
  于是"收到了但当前墙上看不到"。
- 因此 T1 的根因**高度可疑**为：墙名协商不一致 + 写入目标墙不是当前活动墙。
  待改时先复现确认（打印 boardName、写入后的 taskBoards、activeTaskBoardId）。

### T2【交互】"接收/立即拉取"按钮位置不对

- 现状：唯一的手动拉取入口在前端 `src/components/BindCard.tsx:77`（联动绑定卡片里的「立即拉取」），
  即"绑定码/绑定"那一块。
- 用户要求：**移到任务墙板块**；并且桌面端不应只靠手动——需要**自动拉取**。

## 二、当前推送规则（本次核实，供改动时参考）

| 环节 | 位置 | 说明 |
|---|---|---|
| 1 手机发送 | `/taskwall/` 页面 → `POST https://shortcut.326415.xyz/sync/api.php` | body：`action=push`、`board=taskwall`、`bindId`、`mobileToken`、`side=mobile`、`text`、可选 `longText/details/reminderAt/boardName` |
| 2 服务端校验入队 | `server/sync/api.php` 的 `case 'push'` | 统一身份校验（手机用 mobileToken）→ 标题非空、提醒时间格式 → 组 `task`（id `rmt_<24hex>`、createdAt）→ `enqueue_task('taskwall', $bindId, $task)` |
| 3 落盘 | `server/sync/config.php` `queue_path()` | `/www/wwwroot/ShortCut/sync/data/queues/taskwall/<bindId>.json`（flock + 原子替换；队列上限 500 条） |
| 4 桌面拉取 | `sync.rs::pull_taskwall()` → `{action:'pull', board:'taskwall'}` | **peek 不删除**，返回该绑定队列里全部未确认任务 |
| 5 桌面写入 | `sync.rs::pull_taskwall()` 后半段 | 写 `config.taskBoards[].notes[]`；同名墙不存在则新建；便签样式由 `create_task_note()` 随机生成（胶带色/旋转/坐标） |
| 6 桌面确认 | `{action:'ack', board:'taskwall', taskIds:[...]}` | 服务端按 id 删除队列条目（"拉取即删"发生在 **ack 之后**，写入失败则保留） |
| 7 通知 | 桌面写入后发系统通知 | 文案类似"收到 N 条任务，已加入任务墙" |

**推送时机（关键）**：
- 手机端：点发送即入队（实时）。
- 桌面端：**目前没有启动拉取，也没有定时轮询**——`pull_taskwall()` 的唯一调用点是前端
  `BindCard.tsx:77` 的「立即拉取」按钮（`syncPullNow` 命令）。
  ⇒ 这就是"必须手动点、而且按钮还放错地方"的由来；也是 T2 要解决的核心。

## 三、修改计划（待用户确认后执行）

1. **T2 先做（低风险）**：把拉取入口移到任务墙板块；同时给桌面加**自动拉取**
   （启动时一次 + 周期轮询，建议 30~60 秒；并遵守游戏模式冻结时跳过）。
2. **T1 复现与修复**：
   - 复现：手机发一条带墙名的、一条不带墙名的，桌面侧打印实际写入的 boardName / 新建墙 id / activeTaskBoardId；
   - 修复方向（择一或组合）：
     a. 写入后若目标墙不是当前活动墙 → 切到该墙（或至少在 UI 上提示"已加入 XX 墙"）；
     b. 桌面**启动时与墙变动时**上报墙名（`bind.boards.update`），保证手机端列表是真实的墙；
     c. 手机端墙名选择改为"列表 + 可新建"，并在发送时回显最终落点墙名。
   - 验收：手机发任务 → 桌面自动接收 → **当前界面可见**（或明确提示落在哪面墙）→ 手机端墙列表与桌面一致。
