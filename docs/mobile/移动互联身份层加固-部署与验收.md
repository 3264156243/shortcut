## 1. 本轮改了什么

### 1.1 新增：桌面端凭证 `deskToken`（`config.php`）

| 函数 | 作用 |
|---|---|
| `issue_desk_token($bindId)` | 生成 48 位 hex 凭证，服务端只存 `bindings[bindId]['desk']['token_hash']=sha256(token)`；重新签发即轮换 |
| `validate_desk_token($bindId,$token)` | `hash_equals` 比对（与 mobileToken 同构） |
| `has_desk_token($bindId)` | 该绑定是否已签发过桌面凭证（决定兼容通道是否仍然开放） |
| `require_desk_token_enabled()` | 读 `settings.json → requireDeskToken`；打开后桌面侧必须带凭证，无兼容通道 |
| `resolve_identity($bindId,$input)` | **统一身份校验唯一入口**：`mobileToken` → mobile；`deskToken` → desktop；都失败时，仅当"该绑定从未签发过 deskToken 且未开强制模式"才允许旧的 `side` 自报 |

`api.php` 里的 `require_identity()` / 旧的 `require_transfer_identity()` 都只是它的薄封装；`file.php` 直接调 `resolve_identity()`。

### 1.2 行为变化

| 端点 | 变化 |
|---|---|
| `bind.create` | 额外返回 `deskToken`（明文仅此一次） |
| `bind.claimToken`（新增） | 旧绑定引导：用**绑定码**换一次 deskToken；**仅当该绑定从未签发过**可用，限流 5 次/小时/IP |
| `bind.info` | **只有带有效 deskToken 才返回 `code`/`bindUrl`**（原来任何人凭 bindId 就能拿到别人的 6 位绑定码）；始终返回 `deskTokenValid` |
| `bind.resolve` | 只回显调用方输入的码，不再回传服务端存的码 |
| `control.ticket`（role=desktop） | 优先 `deskToken`；仅"旧绑定 + 未开强制模式 + 码正确"时才回退到绑定码 |
| `transfer.*`、`pull`/`ack`/`push`/`board.list`/`bind.boards.update` | 全部改走统一校验（原来是各写一套，桌面侧等于无凭证） |
| `file.php` | **修 S1**：`$action`/`$bindId`/`$fileId` 提到令牌分支之前（原来 `$action` 在赋值前被使用 → 令牌分支恒假 → 跨绑定领取必然 403）；鉴权改走统一入口 |

### 1.3 兼容策略（关键，别跳）

- 兼容通道由**数据**决定：某个绑定只要签发过一次 deskToken，它的免凭证路径立刻失效；没签发过的旧绑定继续可用。
- 新版客户端启动时会自动 `claimToken`，于是"新版装机的绑定"自动升级为强制校验。
- 服务端还有一个**总开关** `settings.json → requireDeskToken`（默认不存在=关闭）。等新版覆盖率够了再打开，即可对全部绑定强制。

### 部署过程中发现并当场修掉的两个问题

1. **带了错误凭证却被放行**（线上验收第 4 项暴露）：原实现里"该绑定未签发过凭证"会回落到兼容通道，
   于是随机 token 也能进。已改为：**只要调方出示了凭证就必须校验通过**，只有完全不带凭证才走兼容通道。
2. **凭证被前端的整份写配置冲掉**（`config.json` 里长度 0）：`writeConfig` 是整份覆盖，
   而凭证一旦签发，服务端就认为该绑定已强制 → 客户端反而被 403。
   已改为：凭证存**独立文件** `%APPDATA%\ShortCut\shortcut\desk-token.json`（与 `window-state.json` 同思路），
   并把 `bind.claimToken` 从"只能签发一次"放宽为"凭绑定码可重复签发/轮换"（与既有 `mobile.bind` 同强度，限流 5 次/小时/IP），
   这样重装或配置丢失也能自愈。
