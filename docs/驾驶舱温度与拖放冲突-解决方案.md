# 驾驶舱温度 × 文件拖放：冲突解决方案（2026-10-09）

## 1. 问题

两个需求互相排斥，且都是"必须"的：

| 需求 | 依赖 |
|---|---|
| 驾驶舱显示 **CPU 温度 / 内存温度** | 需读 MSR / SMBus → LibreHardwareMonitor 要装 ring0 驱动 → **子进程需管理员** |
| **文件拖放到 SC 岛 / 转换面板** | Windows **UIPI** 禁止"资源管理器(Medium) → 管理员窗口(High)"投递 OLE 拖放 → **主进程必须普通权限** |

历史表现：界面曾直接提示「未获取到数据，请以管理员方式运行 ShortCut」→ 用户照做 → **拖放整体失效**
（禁止光标 + 连 Tauri 的 `DragDrop::Enter` 都不触发）。两个问题因此互相触发，反复"复发"。

## 2. 实测边界：冲突其实只有两个字段

同一台机器，只改完整性级别（详细数据见 `tauri-regression.md` §15.3）：

| 字段 | 提权 High | 非提权 Medium |
|---|---|---|
| `cpu.usage` / `gpu.usage` / `memory.usage` | ✅ | ✅ |
| `gpu.temperature` | ✅ 47.4 | ✅ 47.5（NVAPI 不需 ring0） |
| `battery.*` | ✅ | ✅（走 WMI） |
| **`cpu.temperature`** | 76 | **null** |
| **`memory.temperature`** | 52.8 | **null** |

**结论：需要管理员的只有"读那两个温度"这件事。**

## 3. 方案：主进程永不提权，只把"读传感器"的进程放进提权计划任务

```
ShortCut.exe（普通权限 / Medium，永不提权）
  │  拖放、自启、更新、任务墙、文件快传 …… 全部照常
  │
  ├─ 命名管道 server: \\.\pipe\shortcut-hardware-monitor
  │        ▲ 每秒一行 JSON（cpu/gpu/memory/battery）
  │        │
  └─ Start-ScheduledTask ShortCutHardwareMonitor   ← /rl HIGHEST，零 UAC 弹窗
           └─ ShortCut.HardwareMonitor.exe --pipe \\.\pipe\shortcut-hardware-monitor
                 （管理员权限跑 ring0 传感器；写管道失败即自退 = 随主进程回收）

 兜底（未授权 / 任务被删 / 指向旧路径）：直接 spawn 侧车走 stdout
        → 功能全在，只是 cpu/memory 温度显示"需授权"
```

### 3.1 为什么必须改成命名管道

`ShellExecuteEx(Verb=runas)` **无法重定向 stdout**，而原侧车 IPC 正是 stdout 行 JSON。
命名管道不受 UIPI 限制（UIPI 只拦窗口消息、钩子、部分进程操作）。
实测已验证：**非提权进程作 server + 提权侧车作 client，温度数据正常送达**（无需改 DACL）。

### 3.2 为什么不会漏下提权进程

提权子进程**无法**被挂进 Job Object（Medium 进程拿不到 High 进程句柄），所以原来的
"KILL_ON_JOB_CLOSE 随主进程回收"对它失效。替代机制：
- 侧车每秒写管道；**管道断开（主进程退出）→ 写失败 → 侧车自退**；
- 主进程停用时额外 `schtasks /end`，保证不残留。

### 3.3 授权流程（一次，之后零弹窗）

1. 首次点「一次授权并启用温度」→ 以 `runas` 拉起一段 PowerShell（**弹 1 次 UAC**）；
2. 该脚本 `Register-ScheduledTask -RunLevel Highest -LogonType Interactive`，
   注意 `-ExecutionTimeLimit 0`（默认 3 天会被任务计划强杀）；
3. 之后主进程只用 `Start-ScheduledTask` / `Stop-ScheduledTask`（**不需要权限，不弹窗**）；
4. 若 UAC 被取消 → 提示"已取消授权"，继续走 stdout 兜底（仅缺两个温度）。

### 3.4 相关实现点

| 位置 | 内容 |
|---|---|
| `tools/hardware-monitor/HardwareMonitorBridge.cs` | 新增 `--pipe <name>`：`FreeConsole()` 摘掉黑窗 + 命名管道写行；写失败即退出；无参数时保持原 stdout 行为 |
| `src-tauri/src/sidecar.rs` | `mod hw`（计划任务查询/创建/运行、TokenElevation 自检、ShellExecuteEx runas）、`hw_task_ready`、命名管道 server + 读取循环、`stop_cockpit_sidecar`、`cockpit_setup_elevation`、`cockpit_elevation_status`、`CockpitState.epoch` 代数守卫 |
| `src-tauri/src/lib.rs` | 新命令 `cockpitElevationStatus` / `cockpitSetupElevation`；`CockpitState.mode/epoch`；退出清理改走 `stop_cockpit_sidecar`；启动时提权自检告警；**`setIsland` 变更驾驶舱开关时同步侧车** |
| `src/components/CockpitPanel.tsx` | 删掉"请以管理员方式运行"的错误引导；改成「一次授权并启用温度」+ 已授权等待态；以管理员运行时反向告警"拖放会失效" |
| `scripts/run-app.ps1` | 以普通权限启动构建产物并校验 `TokenElevation`，防止再"从提权 shell 起 App" |

### 3.5 顺带修掉的两个问题

1. **岛上"驾驶舱数据"开关以前不起作用**：`startCockpit` 只有主面板「驾驶舱」页会调用，
   `setIsland` 不会同步侧车 → 只在岛上开这个开关时永远没数据。现在 `setIsland` 里同步。
2. **背靠背重启的竞态**：授权成功后要从"普通权限通道"切到"提权通道"（stop → start 紧挨着），
   而旧读取循环退出时会回写 `child` / `mode` / `starting` → 可能踩掉刚起来的新通道。
   现在用 `CockpitState.epoch`（代数）：每次停止 +1，循环只在自己的代数仍有效时才回写。

### 3.6 两处踩过的坑（别再犯）

- **`task_info` 的 PowerShell 脚本里不要出现双引号**：`"$($t.Actions[0].Execute)|…"` 这种写法在
  多层传参时引号会被吞掉，PowerShell 把插值当成管道元素报
  `Expressions are only allowed as the first element of a pipeline`。
  改成 `$t.Actions[0].Execute + '|' + …`（零双引号）后稳定。
- **二进制里搜不到 `match` 分支的字面量是正常的**：`match method { "startCockpit" => … }` 这类
  分支常量会被编译器拆成立即数塞进指令流，**不落地成连续 rodata**（只有当参数传给函数的字面量，
  如任务名 / `--pipe` 才是连续的）。所以"在 exe 里搜不到方法名"不能作为"方法没实现"的证据——
  早先 `syncListDevices` 那次"怪现象"就是这个原因。要核对请比对源码分支名与前端调用名。

## 4. 验收步骤

### 4.1 基础（应全绿）

1. `powershell -ExecutionPolicy Bypass -File scripts/run-app.ps1` → 输出
   `完整性级别=medium` 且 `✅ 普通权限启动成功`。
2. 打开 setch → 驾驶舱：使用率/电池正常；温度区显示「一次授权并启用温度」。
3. 点该按钮 → **弹出一次 UAC** → 同意后 2~5 秒内三个温度出现数值。
4. 关闭 App → 任务管理器中 `ShortCut.HardwareMonitor.exe` **不再残留**。
5. 重开 App（普通权限）→ 进驾驶舱 → **不再弹 UAC**，温度直接出现（零弹窗）。

### 4.2 拖放回归（关键：证明没有把拖放弄坏）

6. 从资源管理器拖 1 个文件到 **SC 球** → 高亮/吸附 → 松手弹格式菜单。
7. 拖文件到 **转换面板** → 进入待转换列表。
8. 日志应有 `[island] 拖入 N 个文件` / `[island] 球上松手，文件数=N` / `[drop] 已 emit converter:drop`。

### 4.3 边界与降级

9. 拒绝 UAC → 提示「已取消授权」，仍走普通权限通道：使用率/GPU 温度/电池正常，
   CPU+内存温度显示"—"，按钮仍在（可重试）。
10. 手动删除计划任务（`Unregister-ScheduledTask -TaskName ShortCutHardwareMonitor -Confirm:$false`）
    → 重启 App → 回退普通权限通道，界面重新提示授权。
11. 侧车路径变化（例如换构建目录）→ `taskExeMatches=false` → 界面重新提示授权，
    重新授权会用 `-Force` 覆盖成新路径。
12. 冻结/游戏模式 → 侧车（含提权实例）被停掉，解冻后自动恢复。

### 4.4 以管理员运行时的自检

13. 故意以管理员启动 → 日志出现
    `[app] 当前以管理员权限运行：…拖放…会被 Windows UIPI 拦掉`，
    驾驶舱顶部出现红色告警，且**不再引导用户提权**。

## 5. 边界与已知取舍

- **只覆盖 Windows**（`mod hw` 非 Windows 为空实现）。
- 计划任务名固定为 `ShortCutHardwareMonitor`；不做安装包内的创建，首次授权即创建。
- 管道名固定且无鉴权：同机同用户可读到传感器数据（本机测试环境可接受；
  正式版若要防伪造，可加一次性 token（侧车首行回传，主进程校验））。
- 用户手动改过任务（改参数/降 RunLevel）→ `hw_task_ready` 判否 → 回退兜底并提示重新授权。

## 6. 回滚

- 删任务：`Unregister-ScheduledTask -TaskName ShortCutHardwareMonitor -Confirm:$false`；
- 代码回滚：`git revert` 本次提交即可 —— 恢复原 stdout 直连通道（温度回到"必须整体提权"的老行为）。
