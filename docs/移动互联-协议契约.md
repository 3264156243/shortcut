## 1. 全局约定

### 1.1 端点

| 用途 | 地址 |
|---|---|
| 所有 JSON 接口 | `POST https://shortcut.326415.xyz/sync/api.php` |
| 文件分片上传 / 下载 | `POST/GET https://shortcut.326415.xyz/sync/file.php` |
| 实时通道（WebSocket） | `wss://shortcut.326415.xyz/relay-ws` |
| 移动 Web 共享 SDK（可读作参考实现） | `GET https://shortcut.326415.xyz/sync/sdk.php`（透传 `web/sdk.js`，带 `no-store`） |

**云域名只有一个**：`shortcut.326415.xyz`（Cloudflare 在前，回源 80）。局域网直连是另一套本地 HTTP，见 §8。

### 1.2 请求 / 响应基本形状

```jsonc
// 请求（api.php）：一律 POST，JSON body，action 为顶层字段
{ "action": "push", "bindId": "…", "mobileToken": "…", "text": "…" }

// 成功
{ "success": true, /* 各接口自己的字段 */ }

// 失败（api.php：业务错误一律 HTTP 200！）
{ "success": false, "message": "任务标题不能为空" }
```

| 规则 | 事实 |
|---|---|
| 方法 | `api.php` **仅 POST**（其他方法 → HTTP 405 `{"success":false,"message":"仅支持 POST 请求"}`）；`OPTIONS` → 204 无 body；`file.php` 允许 `POST, GET, OPTIONS` |
| `Content-Type` | 服务端**不校验**请求头；响应恒为 `application/json; charset=utf-8` |
| CORS | `Access-Control-Allow-Origin: *`，允许头仅 `Content-Type` |
| **错误码** | ⚠️ `api.php` **业务失败也是 HTTP 200**，必须读 `success` 字段判断；⚠️ `file.php` 相反，**用真实 HTTP 状态码**（400/403/404/405/500）**同时**返回 `success:false` |
| 未知 action | `{"success":false,"message":"未知操作"}` |
| 时间字段 | **ISO-8601 带时区偏移**，如 `2026-10-09T02:50:23+08:00`（PHP `date('c')`）。**不是 unix 毫秒/秒**。唯一例外：`push.reminderAt` 是客户端原样透传（Web 端发 `2026-10-09T02:50:23.000Z`） |
| `protocolVersion` | ⚠️ **服务端不校验、不协商、不拒绝**。仅在 `module.list` 回显为 `clientProtocol`。版本兼容**由客户端自己判断** |
| `side` | ⚠️ 仅作**遗留兜底**（无任何凭证 + 该绑定从未签发过 deskToken 时）；有凭证时完全按凭证判定。**新客户端不要依赖它** |
| 后台清理 | 任何请求都可能触发一次数据清理（900 秒节流），属正常行为 |

### 1.3 身份（所有需要鉴权的接口共用）

| 端 | 凭证字段 | 形状 |
|---|---|---|
| 手机 | `mobileToken` | 48 位 hex（`bin2hex(random_bytes(24))`） |
| 桌面 | `deskToken`（兼容 `desk_token`、`token`） | 同上 48 位 hex |

- 服务端**只存 `sha256(token)`**，明文只在签发时返回**一次**；比对用常量时间比较。
- 判定顺序（`resolve_identity`）：
  1. `mobileToken` 命中某条 `side='mobile'` 设备 → 身份 = mobile
  2. `deskToken` 命中某条 `side='desktop'` 设备 → 身份 = desktop
  3. **出示了凭证但没匹配上 → 直接拒绝，绝不降级**
  4. 未出示任何凭证 → 走遗留兜底（新客户端不应出现此情况）
- 失败文案（**字符串契约，客户端要按文案分支**）：

| 情况 | `message` | 客户端应做什么 |
|---|---|---|
| 出示了 mobileToken 但无效 | `移动端绑定已失效，请重新绑定` | **清除本地身份 → 跳绑定页** |
| 出示了 deskToken 但无效 | `凭证已失效，请重新绑定或升级客户端` | 桌面端重新领凭证 |
| 无凭证且该绑定有桌面凭证 | `请升级 ShortCut 到最新版（缺少桌面端凭证）` | — |
| bindId 为空/不存在 | `绑定身份无效` | — |

> ⚠️ **`token` 是危险字段名**：它被当作 deskToken 的别名。安卓端自定义字段时避免使用 `token`（请用 `mobileToken` 或自建命名）。

### 1.4 限流

实现：滑动窗口，按 `<action>:<客户端IP>` 计数，存 `data/rate-limits.json`；**IP 取 `REMOTE_ADDR`（不解析 `X-Forwarded-For`）**。超限返回 `{success:false,message:"…过于频繁…"}`。

| action | 次数 / 窗口 | 超限文案 |
|---|---|---|
| `module.list` | 120 / 60s | 请求过于频繁，请稍后再试 |
| `bind.create` | **5 / 3600s** | 创建绑定过于频繁，请稍后再试 |
| `bind.claimToken` | **5 / 3600s** | 操作过于频繁，请稍后再试 |
| `bind.info` | 120 / 60s | 查询过于频繁，请稍后再试 |
| `bind.query` | 60 / 60s | 查询过于频繁，请稍后再试 |
| `bind.resolve` | 30 / 60s | 验证过于频繁，请稍后再试 |
| `mobile.bind` | **15 / 3600s** | 绑定过于频繁，请稍后再试 |
| `bind.devices` | 120 / 60s | 请求过于频繁，请稍后再试 |
| `bind.device.rename` | 60 / 60s | 操作过于频繁，请稍后再试 |
| `bind.device.remove` | 60 / 60s | 操作过于频繁，请稍后再试 |
| `control.ticket` | 60 / 60s | 请求过于频繁，请稍后再试 |

## 2. 身份与凭证接口

### 2.1 `bind.create` — 新建绑定（桌面端首次使用）

无需身份。

**入参**：`deviceName`（可选，截 30 字，空 → `本机电脑`）

**返回**：
```json
{ "success": true, "bindId": "w9cwEp3mlpwTB4y1e90WpNhN", "code": "F92XSE",
  "deskToken": "<48hex>", "bindUrl": "https://shortcut.326415.xyz/mobile/?bind=<bindId>" }
```
- `bindId`：24 位 base62；`code`：6 位 `[0-9A-Z]`（唯一）
- `deskToken`：**明文只此一次**；服务端只存 sha256
- 副作用：立刻写入一条 `side='desktop'` 设备

**失败**：`创建绑定过于频繁，请稍后再试` / `暂时无法创建绑定，请稍后再试`

### 2.2 `bind.claimToken` — 凭绑定码换桌面凭证

**入参**：`code`（必填，大小写不敏感）、`deviceName`（可选）

**返回**：`{ "success": true, "bindId": "…", "deskToken": "<48hex>" }`（**不返回** `code`/`bindUrl`）

**可重复调用 = 轮换**：每次都签发新 `deskToken`，**旧的立即失效**。

**失败**：`操作过于频繁，请稍后再试` / `绑定码为空` / `绑定码无效` / `签发失败，请稍后再试`

### 2.3 `bind.info` — 查绑定有效性

**入参**：`bindId`（必填）、`deskToken`（可选）

**返回**（⚠️ "无效"也返回 `success:true`）：
```jsonc
{ "success": true, "valid": false }                                  // 绑定不存在
{ "success": true, "valid": true, "bindId": "…", "deskTokenValid": true,
  "code": "F92XSE", "bindUrl": "…" }                                 // code/bindUrl 仅在 deskTokenValid 时出现
```

**失败**：限流文案 / `缺少 bindId`

### 2.4 `bind.query` — 绑定码 → bindId

**入参**：`code`（必填）

**返回**：`{ "success": true, "valid": true, "bindId": "…" }` 或 `{ "success": true, "valid": false, "message": "绑定码无效" }`

**失败**：限流文案 / `绑定码为空`

### 2.5 `bind.resolve` — 绑定码 → bindId + 墙列表

**入参**：`code`（必填）

**返回**：`{ "success": true, "bindId": "…", "code": "F02XSE", "boards": ["默认任务墙"] }`

⚠️ 与 `bind.query` 不同：**绑定码无效时返回 `success:false`**（`绑定码无效`）。

### 2.6 `mobile.bind` — 手机端绑定（安卓端**第一个要实现的接口**）

无需身份。

**入参**：

| 字段 | 必填 | 说明 |
|---|---|---|
| `bindId` | 二选一 | **优先**：若 `bindId` 有效则直接用它，**跳过 code 校验** |
| `code` | 二选一 | 6 位绑定码；`bindId` 无效时用它解析 |
| `deviceName` | 否 | 截 30 字，空 → `我的手机` |
| `deviceKey` | **强烈建议填** | 本机稳定标识，截 64 字。**决定重绑是"原地轮换"还是"新增一台"**（见 §3.4） |

**返回**：
```json
{ "success": true, "bindId": "w9cwEp3mlpwTB4y1e90WpNhN", "code": "F92XSE",
  "mobileToken": "<48hex>", "deviceId": "4be639d19ab30f7bf0f869b6", "deviceName": "我的手机" }
```

**失败**：
- `绑定过于频繁，请稍后再试`
- `绑定码无效`
- `本绑定已绑定 5 台手机（已达上限），请先在电脑端「设置 → 移动互联 → 已绑定设备」里移除不用的设备后再试`（数量由服务端 `settings.json→maxMobileDevices` 决定，默认 **5**，钳 1..20）
- `移动端绑定失败，请稍后再试`

## 3. 设备模型（安卓端必须理解）

### 3.1 存储形状（服务端内部，供理解语义）

`binds.json → binds[bindId].devices[]`：

| 字段 | 语义 |
|---|---|
| `device_id` | 24 位 hex；轮换时**沿用**；`legacy-<slot>-<hash前12>` 表示旧数据投影 |
| `device_key` | **仅手机有**：客户端持久化的稳定标识（桌面端为空串） |
| `device_name` | 显示名，最多 30 字 |
| `side` | `mobile` / `desktop` |
| `token_hash` | `sha256(token)`；**明文不落盘** |
| `bound_at` | 首次绑定时间（轮换时保留） |
| `last_seen_at` | 最后活跃（写入**节流 60 秒**） |

### 3.2 对外投影（`bind.devices` 返回的形状）

```json
{ "deviceId": "…", "deviceName": "我的手机", "side": "mobile",
  "boundAt": "2026-10-09T02:50:23+08:00", "lastSeenAt": "2026-10-09T02:50:23+08:00",
  "current": false }
```
**绝不包含 token_hash。**

### 3.3 令牌规则（安卓端存储要求）

| 令牌 | 形状 | 有效期 | 一次性 |
|---|---|---|---|
| `mobileToken` | 48 hex | **永不过期**（直到被轮换/设备被移除） | 否 |
| `deskToken` | 48 hex | 同上 | 否 |
| WS `ticket` | `base64(json).hmac_sha256_hex` | **600 秒** | 否 |
| `downloadToken` | `dl_` + 48 hex | **900 秒** | **是**（消费即废） |
| 共享接收码 | 6 位 `[0-9A-Z]` | 0.5–24 小时（`transfer.share.hours`） | 否（可多次领取） |

### 3.4 轮换 / 新增的判定（**安卓端最容易踩的地方**）

`mobile.bind` 时服务端按以下顺序找"该更新哪一行"：

1. 传了 `deviceKey`，且已有某台手机的 `device_key` **完全相同** → **原地轮换**（deviceId 不变、`boundAt` 保留、换新 token）
2. 传了 `deviceKey`，且**恰好存在一行**没有 `device_key` 的旧手机行 → **就地接管**该行
3. 都不匹配 → **新增一台**（并检查手机数是否已达上限）

> 结论：**安卓端必须持久化一个随机 `deviceKey`**（首次生成后写入本地存储，不要用 `ANDROID_ID` 之类可能变化的值），否则用户每次重装/清数据后重绑都会在设备列表里多出一台"我的手机"，很快占满上限（默认 5）。等价于 Web 端的 `shortcut-device-key-v1`（24 位 hex）。

### 3.5 设备管理接口

| action | 入参 | 返回 | 备注 |
|---|---|---|---|
| `bind.devices` | 身份 | `{devices:[…], mobileCount, mobileLimit, selfDeviceId}` | `current` 标记本机 |
| `bind.device.rename` | `deviceId`(必填), `deviceName`(可选) | `{deviceId, deviceName}` | 名空 → 按 side 给默认名 |
| `bind.device.remove` | `deviceId`(必填) | `{deviceId, devices:[…]}` | ⚠️ **不能移除自己**：`不能移除当前正在使用的设备（本机），请在另一台设备上操作` |

失败文案：`缺少 deviceId` / `设备不存在或改名失败` / `设备不存在或已被移除`。返回的 `devices` **不含 `current`**。

## 4. 模块契约

### 4.1 `module.list`（无需身份；带身份时附带绑定信息）

**入参**：`protocolVersion`（可选，仅回显）

**返回**（线上真实样本，2026-10-10）：
```json
{
  "success": true, "version": 1, "protocolVersion": 1, "clientProtocol": 1,
  "capabilities": {
    "queue":    { "label": "任务队列", "endpoints": ["push","pull","ack","board.list"] },
    "blob":     { "label": "文件分片", "endpoints": ["transfer.fileInit","transfer.fileComplete","file.php?action=uploadChunk","file.php?action=download"] },
    "realtime": { "label": "实时通道", "endpoints": ["control.ticket","wss://shortcut.326415.xyz/relay-ws"] },
    "rpc":      { "label": "一次性调用", "endpoints": [] }
  },
  "modules": [
    { "id": "taskwall", "label": "任务墙", "icon": "🗂️", "desc": "…", "entry": "/taskwall/",
      "capabilities": ["queue"], "minAppVersion": "2.4.5", "enabled": true, "policy": [] },
    { "id": "fileTransfer", "label": "文件共享", "icon": "📤", "desc": "…", "entry": "/transfer/",
      "capabilities": ["blob"], "minAppVersion": "2.4.5", "enabled": true,
      "policy": { "maxFileMb": 1024, "cloudQuotaMb": 2048, "shareEnabled": true, "maxShareHours": 24, "retentionHours": 24 } },
    { "id": "control", "label": "电脑控制", "icon": "🖥️", "desc": "…", "entry": "/control/",
      "capabilities": ["realtime"], "minAppVersion": "2.4.5", "enabled": true, "policy": [] }
  ],
  "bound": false, "side": "", "policySource": "platform"
}
```

| 字段 | 语义 |
|---|---|
| `version` | **模块清单**版本（`modules.json.version`） |
| `protocolVersion` | **服务端协议版本**（当前 1） |
| `clientProtocol` | 回显客户端传的 `protocolVersion`（未传 → 0） |
| `modules[].enabled` | 来自 `defaultEnabled`（缺省 true）；客户端应跳过 `enabled === false` 或无 `entry` 的模块 |
| `modules[].minAppVersion` | 该模块要求的客户端版本下限。⚠️ **服务端不做任何强制**，是否门禁完全由客户端决定（安卓端建议自行比较） |
| `modules[].policy` | 平台策略（可能被激活后台覆盖）；⚠️ 当前服务端**只强制了 `retentionHours`**，其余字段仅声明 |
| `bound` / `side` | 身份是否有效及端类型；身份失败时**不报错**，只降级为 `false` / `''` |

**复用方式**：安卓端的首页/模块页应当**由 `module.list` 渲染**，不要硬编码模块清单；服务端加模块时客户端零改动。

## 5. 任务墙（queue 能力）

`board` 字段在所有 queue 接口**必须显式为 `"taskwall"`**，否则 → `暂不支持的板块`。

### 5.1 `push` — 手机下发任务
**入参**：

| 字段 | 必填 | 约束 |
|---|---|---|
| `board` | 是 | 必须 `taskwall` |
| `bindId` + 身份 | 是 | — |
| `text` | **是** | 截 120 字；空 → `任务标题不能为空` |
| `longText` | 否 | **严格 `=== true`** 才生效 |
| `details` | 否 | **仅当 `longText === true`** 才读取，截 2000 字 |
| `reminderEnabled` | 否 | 严格 `=== true` |
| `reminderAt` | 否 | 仅当 `reminderEnabled === true`；不可解析 → `提醒时间格式无效`（**原样透传，格式不限**） |
| `boardName` | 否 | 截 40 字 |

**返回**：`{ "success": true, "taskId": "rmt_<24hex>", "deliveredRealtime": true, "desktopOnline": true }`
- `deliveredRealtime` = 中继把唤醒送达了桌面端（桌面在线）。**false 不代表失败**：任务已入队，桌面下次拉取会拿到。
- 队列上限 **500** 条，超限 → `待同步任务已达到上限，请先打开桌面端接收`

### 5.2 `pull` — 拉取任务（**不消费**，可重复拉）
**返回**：`{ "success": true, "tasks": [ { "id": "rmt_…", "text": "…", "longText": false, "details": "", "reminderEnabled": false, "reminderAt": "", "boardName": "", "createdAt": "…" } ], "count": 1 }`

### 5.3 `ack` — 确认消费
**入参**：`taskIds`（数组，**必填**，最多 500，仅接受 `rmt_[a-f0-9]{24}`）
**返回**：`{ "success": true, "removed": 1 }`

### 5.4 `board.list` — 任务墙列表
**返回**：`{ "success": true, "boards": ["默认任务墙", "任务墙 2"] }`

### 5.5 `bind.boards.update` — 桌面端上报墙列表
**入参**：`boards`（数组，最多 50 项，每项截 40 字，去重）
**返回**：`{ "success": true, "boards": [ …清洗后的数组… ] }`

## 6. 文件快传（blob 能力）

### 6.1 分片上传流程（安卓端按此实现）

```
① transfer.fileInit  → 拿到 file.id / chunkSize / chunkCount
② 逐片：file.php?action=uploadChunk（multipart 二进制，chunkIndex 从 0 开始）
③ transfer.fileComplete → 服务端校验分片连续性 + 算全文件 sha256 → 产生文件消息
④ 对端 transfer.messages 里看到 type='file' 的消息 → 用 fileId 下载
```

### 6.2 `transfer.fileInit`（别名 `blob.init`）
| 字段 | 必填 | 约束 |
|---|---|---|
| `name` | 是 | 截 180 字，`\` `/` `\0` → `_`；空 → `文件信息无效` |
| `size` | 是 | `> 0` 且 **≤ 1 GB**（`单个文件不能超过 1 GB`） |
| `mime` | 否 | 截 120 字 |
| `chunkSize` | 否 | 默认 **2 MiB**，钳制 **256 KiB .. 5 MiB** |

**返回**：`{ "success": true, "file": { "id": "file_<24hex>", "name": "…", "size": 123, "mime": "…", "chunkSize": 2097152, "chunkCount": 1, "uploaded": [], "sender": "mobile", "createdAt": "…" } }`

### 6.3 `file.php?action=uploadChunk`（**仅 POST**）

| 字段 | 说明 |
|---|---|
| `bindId` + 身份 | 失败 → **HTTP 403** |
| `fileId` | `file_[a-f0-9]{24}` |
| `chunkIndex` | **从 0 开始**，越界 → `分片序号无效` |
| `chunk` | **multipart/form-data 文件字段（二进制，不是 base64）**，字段名 `chunk` |
| `chunkHash` | 可选，sha256 小写 hex；**传了就必须对**，否则 400 且该分片被删 |

**返回**：`{ "success": true, "fileId": "…", "chunkIndex": 2, "uploaded": [0,1,2] }`
**失败**：`文件标识无效`(400) / `分片序号无效`(400) / `分片接收失败` / `分片哈希校验失败`(400) / `分片保存失败`(500) / `上传会话无效`(已完成会话不能再传)

### 6.4 `transfer.fileComplete`（别名 `blob.complete`）
**入参**：`fileId`
**返回**：`{ "success": true, "message": {…文件消息…}, "sha256": "<hex 或 空串>" }`
**失败**：`文件上传会话不存在` / **`文件仍有分片未上传`**（服务端用 `sort(uploaded) !== range(0, chunkCount-1)` 严格比对：**必须 0..n-1 连续无缺**）

### 6.5 `blob.status` — 断点续传查询
**入参**：`fileId`
**返回**：`{ "success": true, "fileId": "…", "name": "…", "size": 123, "chunkSize": 2097152, "chunkCount": 1, "uploaded": [0], "complete": false, "sha256": "" }`
**失败**：`文件标识无效` / `上传会话不存在`

### 6.6 下载

| 场景 | 请求 | 说明 |
|---|---|---|
| 本人下载 | `GET file.php?action=download&bindId=…&fileId=…&mobileToken=…` | 需身份（403 on fail） |
| 凭下载令牌 | `GET file.php?action=download&token=dl_…` | **无需身份**；令牌**一次性**、900 秒有效 |

**响应**：二进制流。响应头：
```
Content-Type: <mime 或 application/octet-stream>
Content-Disposition: attachment; filename="download"; filename*=UTF-8''<URL 编码的真实文件名>
Content-Length: <int>
X-Content-Type-Options: nosniff
X-Checksum-Sha256: <全文件 sha256>
```
⚠️ `filename="download"` 是**固定字面量**，真实文件名在 `filename*=UTF-8''…`（或消息里的 `name`）。安卓端请用消息里的 `name` 存盘。

### 6.7 其它 transfer 接口

| action | 入参 | 返回 |
|---|---|---|
| `transfer.messages` | 身份 | `{success:true, messages:[…], side:"mobile"\|"desktop"}`；元素：文本 `{id:"msg_…",type:"text",text,sender,favorite:false,createdAt}` / 文件 `{id:"msg_…",type:"file",fileId:"file_…",name,size,mime,sender,favorite:false,createdAt}` |
| `transfer.sendText` | `text`（必填，截 10000 字） | `{success:true, message:{…消息对象…}}` |
| `transfer.delete` | `messageId`（`msg_[a-f0-9]{24}`） | `{success:true, deleted:bool}`（**`deleted:false` 仍是 success:true**） |
| `transfer.share` | `text` 或 `messageId`；`code`（可选 6 位）；`hours`（默认 1，钳 0.5..24） | `{success:true, code:"ABC123", expiresAt:"…"}` |
| `transfer.shares` | 身份 | `{success:true, shares:[{id:"shr_…",code,expiresAt,type,name,size,text,createdAt}]}` |
| `transfer.shareDelete` | `id`（`shr_[a-f0-9]{24}`） | `{success:true, deleted:true}` |
| `transfer.claim` | `code`（**无需身份**） | `{success:true, message:{…}, expiresAt:"…", downloadToken:"dl_…或空串"}` |

> `transfer.claim` 可被**多次**领取同一个 6 位码；每次都会重新签发 `downloadToken` 并作废上一个。

## 7. 实时通道（realtime 能力）—— 电脑控制

### 7.1 流程总览

```
① POST api.php {action:'control.ticket', role:'mobile', bindId, mobileToken} → {success:true, ticket}
② 连 wss://shortcut.326415.xyz/relay-ws，连接后【第一帧】必须发 auth
③ 收到 {t:'auth-ok', desktopOnline} → 之后用 {t:'api', id, path, body} 发指令
④ 收 {t:'api-res', id, ok, status, data} 作为指令回执
```

### 7.2 `control.ticket`

**入参**：`role`（可选：`'desktop'` → 桌面端；**其他任何值（含缺省）都当 `'mobile'`**）、`bindId`（必填）、`mobileToken`（mobile 必填）/ `deskToken`（desktop 必填）

**返回**：`{ "success": true, "ticket": "<base64(payload)>.<hmac_sha256_hex>" }`
ticket payload：`{ "bindId": "…", "role": "mobile", "exp": <unix 秒, +600> }`

**失败**：`绑定身份无效` / `移动端绑定已失效，请重新绑定` / `桌面端凭证无效，请升级 ShortCut 到最新版` / `控制中继密钥不可用，请检查服务器 data 目录权限`（服务端故障，fail-closed）

### 7.3 中继消息协议（**逐字**）

**客户端 → 中继**：

| 消息 | 字段 | 语义 |
|---|---|---|
| `{ auth: { role, bindId, ticket } }` | — | **连接后第一帧必须是它**；校验只看 `ticket`（`bindId` 字段实际不参与校验，权威值来自 ticket） |
| `{ t: 'ping' }` | — | 应用层保活 → 回 `{t:'pong', now}` |
| `{ t: 'api', id, path, body }` | — | **仅手机角色**可用；`path` 必须在白名单，否则回 400 |
| `{ t: 'api-res', id, ok, status, data }` | — | **仅桌面角色**可用（桌面端回执） |

**中继 → 客户端**：

| 消息 | 字段 | 语义 |
|---|---|---|
| `{ t: 'auth-ok', role, bindId, desktopOnline }` | `desktopOnline` **只有手机收得到**（布尔）；桌面端该字段被省略 | 鉴权通过 |
| `{ t: 'auth-fail', error }` | 见下表 | 鉴权失败，**随后立即断开** |
| `{ t: 'pong', now }` | ms 时间戳 | 心跳应答 |
| `{ t: 'desktop-status', online }` | 布尔 | **仅发手机**：桌面上下线通知 |
| `{ t: 'sync-wake', board, count }` | — | **仅发桌面**：任务墙实时唤醒 |
| `{ t: 'api', id, path, body }` | — | 中继 → 桌面 |
| `{ t: 'api-res', id, ok, status, data }` | — | 中继 → 手机（**房间广播**，见下方⚠️） |

`auth-fail.error` 的全部文案：

| error | 触发条件 |
|---|---|
| `missing auth` | 首帧没有 `auth` 对象 |
| `ticket invalid or expired` | 票据验签失败/过期（**所有票据失败原因共用这一条**） |
| `server busy` | 房间数达上限（500）且该 bindId 无既有房间 |
| `too many connections` | 同一 bindId 连接数达上限（**3**：1 桌面 + 2 手机） |

⚠️ **`api-res` 是房间广播**：桌面端的回执会发给该 bindId 房间内**所有**手机。安卓端必须用自己的 `id` 过滤，并把 `id` 按 **String** 归一化比较（中继回包时未做类型强转）。

### 7.4 指令白名单（`path` 只能取这 11 个）

```
/api/ping  /api/type  /api/key  /api/combo  /api/mouse  /api/click  /api/wheel
/api/clipboard/refresh  /api/clipboard/paste  /api/clipboard/clear  /api/lan-entry
```

- 不在白名单 → `{t:'api-res', id, ok:false, status:400, data:{error:'path not allowed'}}`（中继直接回，不转发）
- 桌面离线 → `{t:'api-res', id, ok:false, status:503, data:{error:'desktop offline'}}`
- 桌面端**另有闸门**：面板未开「云端连接」时，除 `/api/ping` 与 `/api/lan-entry` 外一律 503 `{error:'control channel disabled'}`

### 7.5 指令语义（与局域网 HTTP API 完全一致，见 §8.4）

| path | body | 说明 |
|---|---|---|
| `/api/type` | `{text}` | 打字，文本 ≤2000 字节 |
| `/api/key` | `{key}` | 单键，`key` 可传 vk 名（`enter`/`f5`）或数字 |
| `/api/combo` | `{keys:["ctrl","c"]}` 或 `{key:"ctrl+c"}` | 组合键，`+`/`-` 分隔 |
| `/api/mouse` | `{dx,dy}` | 相对移动 |
| `/api/click` | `{button:"left"\|"right"\|"middle"}` | 点击 |
| `/api/wheel` | `{delta}` | 滚轮 |
| `/api/clipboard/refresh` | — | 读电脑剪贴板（含历史）；并发时 429 `busy` |
| `/api/clipboard/paste` | `{text}` | 把文本写入电脑剪贴板并触发粘贴，≤20000 字节 |
| `/api/clipboard/clear` | — | 清空历史 |

### 7.6 连接管理（安卓端要注意的硬约束）

| 项 | 值 |
|---|---|
| 每 bindId 连接上限 | **3**（1 桌面 + 2 手机） |
| 全局房间上限 | 500 |
| 单帧消息上限 | **64 KiB**（超出中继直接丢弃） |
| 中继协议层心跳 | **30 秒**发 WS `ping`；客户端**必须回 `pong`**，否则被 `terminate()` |
| 应用层心跳 | 建议 25 秒发 `{t:'ping'}`（桌面端与网页端都这么做） |
| 半死连接检测 | 网页端 60 秒无任何消息则主动重连，建议安卓端同样处理 |
| 重连间隔 | 3 秒（参考实现） |
| 指令超时 | 8 秒（参考实现；超时回 `status:504`） |
| 桌面重连 | **新桌面连接会顶掉旧连接**（设计如此） |

> ⚠️ **安卓后台限制**：WebSocket 在应用退到后台后会被系统挂起/回收（Doze 更激进）。若要做到"后台仍能实时控制/接收唤醒"，需要**前台服务 + 常驻通知**（Android 14 需声明 `foregroundServiceType`，Android 13+ 需 `POST_NOTIFICATIONS` 权限）。**前台限定是当前 Web 客户端的现状**，安卓端可以做得更好，但要做好功耗与合规权衡。

## 8. 局域网直连（局域网控制）

### 8.1 为什么需要它

云端中继链路稳定但有 30–80ms 延迟；手机与电脑在同一 Wi-Fi 时，直连局域网 HTTP 服务只要 5–15ms。

### 8.2 一键直连（**推荐安卓端实现的路径**）

```
① 手机经【已建立的云端 WS 通道】发 {t:'api', path:'/api/lan-entry', body:{}}
② 桌面端回 {t:'api-res', ok:true, status:200, data:{...}}
③ 手机按 data 直接跳转/请求局域网地址
```

**`/api/lan-entry` 的 `data` 形状**：

| 桌面端状态 | 返回 |
|---|---|
| 未开启「局域网直连」 | `{ "running": false }` |
| 已开启 | `{ "running": true, "port": 9823, "url": "http://192.168.1.5:9823", "urls": ["http://192.168.1.5:9823"], "token": "<48hex>", "pairCode": "123456", "authMode": "pair" }` |

- `token` 是桌面端预授权的会话令牌，**随「停止局域网直连」立即失效**。
- 该接口**不受桌面端「云端连接」开关限制**（局域网模式下也能问），但需要云端 WS 通道在线。
- **只在云端中继通道上暴露**；局域网 HTTP 服务本身**不提供**该接口（避免同网段任何人白拿令牌）。

### 8.3 局域网 HTTP 服务（桌面端 `http://<ip>:9823`）

| 项 | 说明 |
|---|---|
| 监听 | `0.0.0.0:9823`（端口可在桌面端配置） |
| 鉴权 | 默认 `authMode='pair'`：需先 `POST /api/pair` 用 6 位绑定码换 `token`；之后所有接口带 `Authorization: Bearer <token>`（或 `x-token`） |
| 预授权 | 用 §8.2 的 `token` 直接当 Bearer 令牌即可，**无需 pairing** |

### 8.4 局域网 API 清单

| 方法 路径 | 鉴权 | 入参 → 返回 |
|---|---|---|
| `GET /api/config` | 否 | → `{authMode, requirePair, basePath}` |
| `GET /api/status` | 否 | → `{running, port, authMode, pairCode?, clients?, injector, urls}` |
| `POST /api/pair` | 否 | `{code}` → `{token}`；码错 401 `{error:"绑定码错误"}`；模式非 pair 400 |
| `POST /api/unbind` | 是 | → `{ok:true}` |
| `POST /api/ping` | 是 | → `{ok:true, injector, authMode}` |
| `POST /api/type` | 是 | `{text}`（≤2000 字节）→ `{ok, injector}`；空 400 `empty`、超长 400 `too long` |
| `POST /api/key` | 是 | `{key}` → `{ok}` |
| `POST /api/combo` | 是 | `{keys:[…]}` 或 `{key:"ctrl+c"}` → `{ok}` |
| `POST /api/mouse` | 是 | `{dx,dy}` → `{ok}` |
| `POST /api/click` | 是 | `{button:"left"\|"right"\|"middle"}` → `{ok}`（默认 left） |
| `POST /api/wheel` | 是 | `{delta}` → `{ok}` |
| `POST /api/clipboard/refresh` | 是 | → 剪贴板内容 + 历史；并发 429 `{error:"busy"}` |
| `POST /api/clipboard/paste` | 是 | `{text}`（≤20000）→ `{ok, injector}` |
| `POST /api/clipboard/clear` | 是 | → `{ok:true}` |
| `POST /api/reset-code` | 本机限定 | 仅 `127.0.0.1` 可调，否则 403 `localhost only` |
| `GET /` 及其它路径 | — | 静态控制页（`resources/sj/`） |

鉴权失败统一：**HTTP 401** `{ "error": "unauthorized", "authMode": "pair" }`。
所有接口**成功用 HTTP 200 + 自己的 JSON 形状**（这里**没有** `success` 字段，与 api.php 不同！）。

### 8.5 安卓端接入局域网直连的注意事项

1. **明文 HTTP**：`http://192.168.x.x:9823` 在 Android 9+ 默认被拦。必须配 `network_security_config.xml` 放行私网明文（或 debug 构建开 `usesCleartextTraffic`）。**不配 = 功能静默失败**。
2. **地址会变**：每次「局域网直连」启动都要重新向 `/api/lan-entry` 询问，不要缓存 IP。
3. **不在同一网络时**：局域网地址不可达，应提示用户并有回退到云端连接的路。（服务端无法判断"手机与电脑是否同一局域网"，客户端自行容错。）
4. **令牌生命周期**：`token` 只在桌面端保持「局域网直连」运行期间有效；桌面端停止后所有请求 401，客户端应回落到云端或提示。

## 9. 桌面一次性指令（rpc 能力）

| action | 入参 | 返回 |
|---|---|---|
| `module.invoke` | `module`（默认 `desktop`）、`method`（**必填，白名单 `open`/`ping`**）、`params`（仅标量：键 ≤32 字节，字符串值 ≤512 字） | `{success:true, invokeId:"inv_<24hex>"}` |

失败：`缺少 method` / `不支持的指令: <method>` / `指令投递失败` / `缺少 invokeId`。
⚠️ `done:false` **不代表失败**，只表示还没有回执。

## 10. 安卓端实现清单（**本节由安卓侧维护**）

### 10.1 必做

1. **持久化 `deviceKey`**（随机 24 位 hex，首次生成后保存），`mobile.bind` 时始终带上传。见 §3.4。
2. **区分两种失败**：`api.php` 看 `success` 字段（HTTP 恒 200）；`file.php` 看 HTTP 状态码。
3. **按文案分支**：收到 `移动端绑定已失效，请重新绑定` → 清本地身份 + 跳绑定页。
4. **时间解析**：ISO-8601 带 `+08:00` 偏移；`reminderAt` 是自己传的、原样回来。
5. **分片**：`chunkIndex` 从 0 开始、multipart 二进制、片数用服务端返回的 `chunkCount`（不要自己算）。
6. **WS**：首帧 auth；处理 `auth-ok.desktopOnline`；`desktop-status` 更新在线状态；`api-res` 按 `id`（String 归一化）过滤；回 `pong`；25 秒应用层 ping；断线 3 秒重连。
7. **模块清单**用 `module.list` 渲染，别硬编码。
8. **一键直连**：先经云端 WS 问 `/api/lan-entry`，再走局域网 HTTP；配好明文网络策略。

### 10.2 已知陷阱（我们踩过的）

| # | 陷阱 | 后果 |
|---|---|---|
| 1 | 不带 `deviceKey` 重绑 | 设备列表堆出多台"我的手机"，很快到上限 5 |
| 2 | 每次指令都换 ticket | 触发 `control.ticket` 限流（60/分钟） |
| 3 | 用 HTTP 状态码判断 api.php 成败 | 永远判成"成功" |
| 4 | 自己算分片大小 | `分片序号无效` 或残片（必须回读 `chunkCount`） |
| 5 | 分片传 base64 | `分片接收失败` |
| 6 | 用 `side` 做鉴权 | 凭证正确时 `side` 无意义；凭证错误时不会因 `side` 放行 |
| 7 | 缓存局域网 IP | 换网络后连不上，且不会自愈 |
| 8 | 依赖服务端做版本门禁 | 服务端**不校验** `protocolVersion`，旧客户端不会被拒（也不会被提醒） |
| 9 | 把 `token` 当自定义字段名 | 它被当作 deskToken 别名，可能被误判身份 |
| 10 | 假设 `bind.info`/`bind.query` 失败时 `success:false` | 它们返回 `success:true, valid:false` |
