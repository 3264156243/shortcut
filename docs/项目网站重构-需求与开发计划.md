## 1. 为什么要重构

现有网站是**单文件 809 行**（`website/index.html`，34 KB，CSS/JS 全内联），线上部署的
`/www/wwwroot/ShortCut/index.html` 与仓库一致（md5 `df20996b…`，最后更新 9-7）。
实测出 **6 个硬问题**：

| # | 问题 | 证据 |
|---|---|---|
| 1 | **页面直接显示占位文字** | 6 处「放入 ShortCut 主界面整体截图」「截图位置」等占位框，访客看到的是"待补图" |
| 2 | **零真实截图** | 全文 0 个 `<img>`，无一张产品界面 |
| 3 | **下载链接写死旧版** | `dlDirect` → `ShortCut-2.4.4-Setup.exe`（Electron 版），当前是 **2.5.1 Tauri** |
| 4 | **内容严重滞后** | "安卓" 0 处、"Tauri" 0 处；手机控电脑仅 1 处；产品已从 Electron 迁移完 |
| 5 | **品牌色不一致** | 网站用蓝 `#4f8cff`，而桌面产品主色是**橙 `#e85d04`**（`src/index.css:15`） |
| 6 | **过时/错误的对外信息** | 底部写「MIT License」（项目已改专有）、只链 Gitee（无 GitHub） |

**结论**：不是修补，是从零重构 —— 结构、视觉、内容、数据来源全部重做。

## 2. 已确认的产品决策

| # | 决策项 | 结论 | 理由 |
|---|---|---|---|
| 1 | **定位** | **产品官网**：介绍卖点 + 下载 + 更新日志 | 面向想用这个工具的人，重点是"能帮我做什么" |
| 2 | **站点形态** | **多页面站点**（非单页长滚动） | 功能演示独立成页，首页只做概览与分流 |
| 3 | **技术栈** | **多文件纯静态**（html + css/ + js/ + assets/），**无构建** | 部署 = 拷文件；加载最快；国内访问最稳；无需维护工具链 |
| 4 | **页面清单** | 首页 + 6 个功能页 + 下载页 + 更新日志页 + FAQ 页 | 见 §3 |
| 5 | **导航** | 顶部固定导航 + 「功能」下拉菜单；手机端汉堡菜单 | 多页面必需 |
| 6 | **子页深度** | 中等：大标题 + 一句话卖点 + 2~3 张图 + 3~5 个能力点 + 上一/下一功能 | 内容扎实但不臃肿 |
| 7 | **截图** | **我来截**（驱动应用逐屏截取）→ **你审图挑用** | 我的模型不支持读图，无法判断构图与隐私，故必须人工过目 |
| 8 | **下载渠道** | **四渠道平铺**：自家服务器 / 蓝奏云 / Gitee / GitHub | 用户指定 |
| 9 | **蓝奏云** | 保留，**点按钮弹层显示提取码**（当前写死 `9akr`） | 比直接把码印在页面上友好 |
| 10 | **安卓端** | **公开下载**，指向 `updates/android/`，版本信息动态读取 | 已实测线上为 0.2.4 / versionCode 6 / 35.32 MB |
| 11 | **更新日志** | 最新版读 `latest.json` + 历史版本手工维护在 `data.js` | 不改发版流程，改动最小 |
| 12 | **文档中心** | **不做**；只留 FAQ + 仓库入口 | 仓库私有，链 docs 会是死链 |
| 13 | **路线图** | **不放** | 访客更关心现在能干什么 |
| 14 | **手机适配** | **必须**（3 断点），手机打开要好看好用 | 官网链接常在微信/手机里打开 |
| 15 | **部署** | 我改完直接 scp 到服务器并做公网回归 | 用户指定 |
| 16 | **GitHub** | **先放按钮**（标注"私有仓库，暂不开放"），后期转公开 | 用户明确"先放，我后期公开" |
| 17 | **视觉参考** | `https://deskbox.fun` | 用户指定的样例站 |

## 3. 信息架构

### 3.1 页面清单（9 页）

```text
website/
├── index.html                 首页：概览 + 卖点卡 + 一键下载 + 更新摘要

│   ├── shortcut.html          快捷启动（模块 shortcuts）
│   ├── taskwall.html          任务墙（tasks）

│   ├── transfer.html          文件快传（fileTransfer）
│   └── android.html           安卓端（独立 App）
├── download.html              下载：四渠道 + 版本/体积/日期 + 系统要求
├── changelog.html             更新日志：版本时间线
└── faq.html                   常见问题
```

### 3.2 顶部导航

```text
Logo「ShortCut」  首页 │ 功能 ▾ │ 下载 │ 更新日志 │ 常见问题        [ 下载 v2.5.1 ]
                            └─ 快捷启动 / 任务墙 / SC球 / 手机控电脑 / 文件快传 / 安卓端
```

- 桌面端：固定顶栏，滚动时加深背景与阴影
- 手机端（≤640px）：折叠为汉堡菜单，全屏抽屉

### 3.3 各页内容大纲

**首页**（7 段）
1. **Hero**：主标题 + 副标题 + 版本徽标 + 「下载」主按钮 + 「查看功能」次按钮 + **主界面截图**
2. **产品概览**：一句话定位 + 3 个数据点（体积 7 MB / 内存 / 快捷键数量）
3. **功能卡网格**（6 张，对应 6 个功能页）：图标 + 名称 + 一句话 + 「了解更多 →」
4. **移动互联专段**：手机 + 电脑联动示意（含扫码/一键直连卖点）
5. **核心优势**（3~4 条）：本地数据不上传 / 全局快捷键 / 离线可用 / 开机自启
6. **更新摘要**：最新版本号 + 日期 + 3 条要点 + 「查看全部更新」
7. **结尾 CTA**：「试试 ShortCut vX.Y.Z」+ 下载按钮

**功能子页**（统一模板）
```text
面包屑 › 功能名 | 大标题（一句话价值） | 一段说明
2~3 张截图 / 示意图（带说明文字）
3~5 个能力点（图标 + 标题 + 一句描述）
相关快捷键（如有）
上一篇 / 下一篇 功能导航  +  底部下载 CTA
```

**下载页**
- 最新版卡片：版本号 / 发布日期 / 安装包体积 / 系统要求（Win10/11 x64）
- 四渠道卡片（平铺）：自家服务器（推荐）/ 蓝奏云（弹层显示提取码）/ Gitee / GitHub
- 安卓端卡片：版本 0.2.4 / 35.32 MB / 「下载 APK」
- 安装说明（3 步）+ 常见安装问题（SmartScreen 提示等）

**更新日志页**
- 最新版（从 `latest.json` 读 version / pub_date / notes）
- 历史版本时间线（`data.js` 手工维护，含 2.5.1 / 2.5.0 / 2.4.6 / 2.4.5 …）

**FAQ 页**
- 分类：安装与更新 / 功能使用 / 移动互联 / 隐私与数据 / 安卓端
- 每条：问题 + 折叠答案（`<details>`，无 JS 也能用）

### 4.3 从 deskbox.fun 借鉴什么（以及不借鉴什么）

**借鉴**（提取自其 CSS 与结构）：
- 页面节奏：`hero → product → values → native → faq → final CTA` 的线性叙事
- 深色表面多层灰（`#161719` / `#20242a`）+ 单一高饱和强调色点缀
- 金色 `#d4a853` 用于「推荐/支持者渠道」的边框与顶部渐变线（其 `download-channel-card-supporter`）
- 卡片圆角 + 胶囊按钮 + 克制的阴影
- 下载渠道做成**卡片网格**（正好对应我们的四渠道）
- 文案口吻：短句、讲"不用改变习惯"这类实际收益

**不借鉴**：
- 不复制其布局细节与品牌元素（避免看起来像 DeskBox 换皮）
- 不引入 Next.js / Tailwind 构建链（我们保持纯静态）
- 不做中英双语（本期不做，见 §9 待确认）
- 不做其"路线图/帮助/反馈/关于"等页面（本期范围外）

## 5. 技术方案

### 5.1 目录结构

```text
website/
├── index.html
├── download.html
├── changelog.html
├── faq.html
├── features/{shortcut,taskwall,scball,control,transfer,android}.html
└── assets/
    ├── css/site.css        # 设计令牌 + 组件（全站共用）
    ├── css/pages.css       # 页面级微调
    ├── js/site.js          # 导航注入、滚动状态、下拉菜单、弹层、滚动入场
    ├── js/data.js          # ★ 站点数据单一真源（版本、渠道、功能清单、历史日志、FAQ）
    ├── js/download.js      # 读 latest.json + HEAD 获取安装包体积
    ├── js/changelog.js     # 最新版（latest.json）+ 历史（data.js）
    ├── img/                # 图标、装饰、二维码
    └── screenshots/        # 产品截图（我截）
```

### 5.2 导航与页脚的维护方式

- **`site.js` 注入** `nav` 与 `footer`（9 个页面只维护一处）
- `<noscript>` 内提供纯文本降级链接列表（保证 JS 关闭也能跳转）
- 当前页高亮：由 `data-page` 属性匹配

### 5.3 数据来源（避免再次写死旧版本）

| 数据 | 来源 | 说明 |
|---|---|---|
| 桌面版本号 / 日期 / 更新说明 | `GET /updates/latest.json` | 同域，无 CORS 问题；`cache: 'no-store'` |
| 安装包体积 | `HEAD /updates/<url>` → `Content-Length` | 已实测可用（7.34 MB） |
| 安卓版本 / 体积 / APK 地址 | `GET /updates/android/latest.json` | 已实测：0.2.4 / versionCode 6 / 35.32 MB |
| 历史版本日志 | `assets/js/data.js` | 手工维护 |
| 蓝奏云链接 / 提取码 | `assets/js/data.js` | 手工维护（改动只一处） |
| Gitee / GitHub 地址 | `assets/js/data.js` | GitHub 标注"私有仓库，暂不开放" |

> **失败降级**：任一 fetch 失败时，使用 `data.js` 里的兜底值并**不显示错误**（避免官网出现报错）。

### 5.4 SEO / 分享

- 每页独立 `<title>` 与 `<meta name="description">`
- Open Graph + Twitter Card（`og:title` / `og:description` / `og:image`）
- `og:image` 统一用一张 1200×630 品牌图（我来做，或从截图裁）
- `theme-color: #0b0e14`
- 语义化标签：`header/nav/main/section/article/footer`，标题层级 `h1→h3`

### 5.5 可访问性与性能

- 对比度：正文 `--text` 对 `--bg` 满足 WCAG AA
- 键盘可达：下拉菜单 `Tab`/`Esc` 可用；弹层焦点锁定 + `Esc` 关闭
- 图片 `alt` 必填；装饰图 `aria-hidden`
- 零外部依赖（不引 CDN 字体/图标/JS）；截图用 WebP + `loading="lazy"`
- 目标：首页首屏 < 500 KB（不含懒加载截图）

> ⚠️ **实测补充（2026-10-18）**：本站域名走 Cloudflare 代理，CF 会在**所有 HTML 响应末尾自动注入**
> Web Analytics 脚本（`static.cloudflareinsights.com/beacon.min.js`，已确认首页与 `/mobile/` 均有）。
> 这带来两点：
> 1. 即使我们代码零依赖，页面实际仍有 **1 个外部请求**；
> 2. **访问统计已由 CF 提供**，无需自建（原 §9 待确认项 #6 因此关闭）。
>
> 若希望彻底零外部请求，可在 CF 后台关闭 Web Analytics，或用 CSP 阻止该域名。
