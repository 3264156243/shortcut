# 主程序两处 bug 修复：更多菜单被遮盖 + 穿透快捷键/开关失效（2026-10-13）

## 一、任务墙「更多板块」菜单被任务条遮盖

### 现象
在任务墙板块点击左侧栏「更多」，弹出菜单的层级低于任务条（便签）层级，被盖住。

### 根因
`ModuleSidebar.tsx` 的「更多」弹出菜单用的是 **`z-50`**，而同项目 `TaskBoard.tsx` 顶部早就写明了层级约定：

```
1 .. 999      任务便签（新便签 / 刚拖过的在上层；store 里有 TASK_Z_CEILING=999 上界与归一化）
1000          全局弹层（设置/导入/添加编辑快捷方式/快捷键/更新/转换设置…）
1100/1110     快捷方式右键菜单   1200 Toast
10000         任务便签「拖动中」的临时值
12000/13000   撕碎动画 / 撕纸机特效
14000+        任务板自身弹层（任务清单设置 < 重命名任务墙 < 任务编辑）
```

便签的 z-index 是 **按"当前最大值 + 1"递增** 的：只要便签数量/操作次数让某个便签超过 50，
它就会盖住 `z-50` 的「更多」菜单；拖动中的便签更是直接 10000。约定里已经写明"≥1000 的弹层高于便签"，
只有这个菜单没跟上。

### 修复
- `ModuleSidebar.tsx`：弹出菜单 `z-50` → **`z-[11000]`**（压得住便签与拖动中的 10000，
  又不至于盖住 12000/13000 特效与 14000+ 任务板弹窗），并在代码里写明为什么取这个值。
- `TaskBoard.tsx` 的层级约定注释里补上 `11000 — 左侧栏「更多」菜单` 这一档，
  避免以后有人再把它改回低值。

> 该菜单本身已有"点击外部 / Esc 关闭"逻辑，所以提高层级不会出现"菜单压住全局弹窗"的副作用。

## 二、「启用穿透」开关与 Alt+B 快捷键"看起来无效"

### 现象
用户报告：启停穿透的快捷键只有软件面板打开时才有用；不打开面板时按了没反应。

### 实测结论：**快捷键本身是全局有效的**
直接用 `keybd_event` 发 Alt+B，日志（面板处于隐藏状态时）正常打出：

```
[hotkey] 触发: control+alt+keyb → control+alt+b
[ball] 快捷键切换穿透 → false
```

`configured_hotkeys()` 里确实包含 `ball_passthrough_shortcut()`，注册在启动时完成
（只有游戏模式冻结会整份注销）。所以"没用"的不是快捷键，而是**它的效果看不出来**。

### 真正的根因（两个叠加）

**① 我上一轮引入的换算 bug**：`cursor_over_island_content()` 里用
`scale = 窗口宽 / ISLAND_WIDTH` 求缩放比。这在窗口尺寸正常时是对的，
但当时岛窗口处于异常尺寸（见下），算出 `1721/360 = 4.78`（真实缩放 1.5）
→ 光标 → 窗口坐标换算全错 → "光标是否在球上"永远为否
→ 开关开着=穿透、关着也=穿透 → **两种状态看起来完全一样**，用户自然认为"开关/快捷键没用"。

**② 岛窗口被撑成了整个桌面**：枚举该进程窗口时发现岛窗口是
`pos=(-7,-7) size=1721×1081`（逻辑像素；虚拟屏为 1707×1067），而它本应是 360×340。
窗口一大，"可见内容矩形"的窗口内坐标也随之变成 x≈742（正常应为 x≈68），
拖放守卫的"光标是否在岛上"几乎处处为真（历史上日志里 `拖拽活跃` 反复翻转就是这个原因）。

> ⚠️ **尚未定位是谁把岛窗口改大的**：现有代码里没有任何地方对 island 调 `set_size`
> （`island_bounds()` 只会返回 ≤360×340，前端也没有直接调用 Tauri 窗口 API，
> `resizeWindow` 只有 tasklist 在用且是 340×h）。因此本轮的做法是**加不变式自愈 + 留痕**，
> 而不是假装已经找到根因。

### 修复

1. **换算改用真实缩放因子**（`windows.rs`）：
   - 新增 `island_logical_size(win)`：`inner_size() / scale_factor()`（不再用"宽/常量"）。
   - `cursor_over_island_content()` 用它换算光标坐标。
2. **命中框合理性过滤**：新增 `hit_rect_is_sane()`，上报值若落在窗口之外（异常状态的典型特征）
   就忽略，退回"整窗"——宁可整窗可交互，也不要出现"开关看起来坏了"。
3. **岛窗口尺寸不变式自愈 + 大声留痕**：新增 `enforce_island_size()`，
   在拖放守卫轮询里每 ~2 秒体检一次；一旦发现尺寸 != `island_bounds()` 就 `set_size` 纠正，
   并打 `[island] 窗口尺寸异常 …×…（应为 …×…），已纠正。请把这条日志交给开发者定位来源`。
   下次复现时这条日志会给出**时间点**，便于顺着时间线找出元凶。
4. 顺带把"拖放守卫"的快轮询条件与命中框口径统一（仍只在"开关关 **且** 非展开态"时 40ms）。

### 实测验证（本机，真实路径）

岛窗口恢复正常 360×340 后：

| 场景 | 期望 | 实测日志 |
|---|---|---|
| 开关关 + 光标在球上 | 不穿透（球可点） | `穿透生效 = false` ✅ |
| 开关关 + 光标移开 | 穿透（不挡桌面） | `穿透生效 = true` ✅ |
| 开关开 + 光标在球上 | 恒定穿透 | `请求=true 实际可穿透=true ex=0xC0138` ✅ |
| 开关关 + 光标在球上 | 不穿透 | `请求=false 实际可穿透=false ex=0x40118`（0x20 位已清）✅ |
| 配置落盘 | 持久化 | `island.ballClickThrough` 随开关变化 ✅ |

修复前同一条是 `请求=false 实际可穿透=true ex=0xC0138`——即用户看到的"状态变了但还能穿透"。

> 注：`ex` 的 `0x20` 位是 `WS_EX_TRANSPARENT`。它是否置位，就是"这个窗口到底穿不穿透"的物证。

## 三、排查小抄（本轮踩过的坑）

1. **应用日志是 UTF-8**：用 PowerShell `Select-String` 时必须带 `-Encoding UTF8`，
   否则中文模式匹配不到（本轮因此误判过一次"没有上报"）。
2. **日志会就地轮转**：`tauri.log` 只保留最新一段，早期启动日志会被挤掉。
3. **本机 pwsh 是 DPI-unaware**：`GetDpiForSystem()` 会谎报 96，`SetCursorPos`/`GetWindowRect`
   拿到的都是"虚拟化"坐标（真实缩放 1.5）。跨进程量窗口/放光标时要按 1.5 换算。
4. **改前端必须按顺序重建**：`npm run build` 先、`cargo build` 后，否则 exe 里是旧前端。
