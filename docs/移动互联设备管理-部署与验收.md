# 移动互联 · 设备管理与多设备模型（部署与验收）

> 日期：2026-10-09
> 起因：设置里只有「联动绑定」（二维码 + 绑定码），**没有对已绑定设备的管理**（例如移除）。
> 排查后发现根因比"少个界面"更深：服务端的数据模型里根本没有"设备集合"这个概念。

---

## 一、根因（改造前实测）

线上绑定 `F92XSE` / `w9cwEp3mlpwTB4y1e90WpNhN` 在 `binds.json` 里的真实形态：

```
mobile: {                        desk: {
  device_id    = 32dfde4f…         token_hash = 01d92a4f…
  device_name  = 我的手机          issued_at  = 2026-10-09T02:43:13
  token_hash   = 1baa8418…       }
  bound_at     = 2026-10-09T02:50:23
  last_seen_at = 2026-10-09T02:50:23   ← 与 bound_at 完全相同
}
```

| # | 缺口 | 后果 |
|---|---|---|
| 1 | `mobile` / `desk` 是**单槽**，`issue_mobile_token()` 覆写整个槽 | 第二台手机扫码即**静默顶掉**第一台（旧手机此后全部 403，且毫无提示） |
| 2 | `last_seen_at` 只在绑定时写一次，之后从不更新 | 即使显示也是假数据 |
| 3 | 桌面端只见二维码/绑定码 | 看不到设备清单，也没有撤销入口 |

## 二、改动清单

### 服务端

| 文件 | 改动 |
|---|---|
| `server/sync/config.php` | 新增设备模型：`max_mobile_devices()`、`bind_devices()`（旧单槽投影）、`match_device()`、`store_devices()`、`list_devices()`、`register_device()`（含上限与原地轮换）、`touch_device_last_seen()`（60 s 节流）、`remove_device()`、`rename_device()`；`issue_mobile_token()/issue_desk_token()/validate_*_token()/has_desk_token()` 全部切到设备模型；`resolve_identity()` 额外返回 `deviceId` |
| `server/sync/api.php` | `require_identity()` 命中后刷新最后活跃；`bind.create` / `bind.claimToken` 接受 `deviceName`；`mobile.bind` 接受 `deviceKey` 并按上限给明确拒绝；新增 `bind.devices` / `bind.device.rename` / `bind.device.remove` |
| `server/sync/web/sdk.js` | 新增 `deviceKey()`（本机稳定标识，localStorage 长期保存）；`mobile.bind` 自动携带 |
| `settings.json`（可选） | `maxMobileDevices`：手机设备上限，缺省 5，钳制 1..20 |

### 桌面端

| 文件 | 改动 |
|---|---|
| `src-tauri/src/sync.rs` | `sync_list_devices()` / `sync_remove_device()` / `sync_rename_device()`；`device_api()` 统一出口，**凭证失效时自愈重领并重试一次** |
| `src-tauri/src/lib.rs` | 注册 `syncListDevices` / `syncRemoveDevice` / `syncRenameDevice` 三条命令 |
| `src/components/DeviceCard.tsx` | 新增设备列表卡片：图标 + 名称（可改名）+ 端类型 + 绑定时间 + 最后活跃 + 两步确认移除 + 本机标记 |
| `src/components/SettingsPanel.tsx` | 在「联动绑定」下方挂载 `DeviceCard` |
| `src/store/index.ts` | 三条命令的 TS 类型声明 |

## 三、部署步骤（已执行）

```bash
# 1) 上传到暂存目录并做语法检查（PHP 7.4 亦兼容，线上站点跑 8.2）
install -o www -g www -m 644 config.php /www/wwwroot/ShortCut/sync/config.php
install -o www -g www -m 644 api.php    /www/wwwroot/ShortCut/sync/api.php
install -o www -g www -m 644 sdk.js     /www/wwwroot/ShortCut/sync/web/sdk.js

# 2) 备份数据（注意真实路径在 sync/data/ 下，不在 sync/ 下）
cp -a /www/wwwroot/ShortCut/sync/data/binds.json \
      /www/wwwroot/ShortCut/sync/data/binds.json.bak-dsh-devices-<时间戳>
```

无需数据迁移脚本：旧单槽在读取时投影、在下一次写入时并成 `devices[]`。

### 4.1 一次性绑定上的功能验收（不触碰真实绑定）

`bind.create` 新建测试绑定后逐项验证，**28 项通过**：

| 用例 | 结果 |
|---|---|
| 5 台手机绑定（不同 `deviceKey`） | 全部成功 |
| 同一 `deviceKey` 重绑 | `deviceId` 不变（`88e177ed…` → `88e177ed…`）= **原地轮换**；旧令牌立即失效 |
| 第 6 台 | 被拒，提示：`本绑定已绑定 5 台手机（已达上限），请先在电脑端「设置 → 移动互联 → 已绑定设备」里移除不用的设备后再试` |
| `bind.devices` | 6 台（1 电脑 + 5 手机）；`mobileCount=5`、`mobileLimit=5`；恰好 1 台 `current`；**响应中不含任何 token 字段** |
| `bind.device.rename` | 成功，列表随即反映新名（`书房平板`） |

## 五、已知边界与取舍

1. **桌面仍为单台语义**：一个绑定只有一份 `deskToken`（多台电脑会互相顶掉，与改造前一致）。
   多电脑共存需要"每台电脑一个 desk 设备 + 各自凭证"，属于下一步，不在本轮。
2. **移除不等于清理**：被移除设备提交过的任务/消息/文件仍保留（数据按绑定归属）。
3. **设备上限只约束手机**：`maxMobileDevices` 只管 `side=mobile`。
4. **心跳 60 秒节流**：`lastSeenAt` 最坏有 60 秒误差，换取"不给每个请求加一次写锁"。
5. **Electron 侧未接线**：`electron/preload.ts` 未加这三条命令（迁移方向是 Tauri 2）；
   Electron 构建下 `DeviceCard` 会显示"设备列表暂不可用"，不影响 Tauri 版。

## 六、回滚

```bash
cp -a /www/wwwroot/ShortCut/sync/data/binds.json.bak-dsh-devices-<时间戳> \
      /www/wwwroot/ShortCut/sync/data/binds.json
# 再回退 config.php / api.php / sdk.js 到上一提交版本即可
```

注意：回滚代码但**不回滚数据**也安全 —— 旧代码只读 `mobile` / `desk` 槽，会看不到已迁移的设备；
因此数据与代码必须一起回滚。
