## 0. 一句话目标

**先把框架定死，再填功能。** 衡量标准不是"这版有几个功能"，而是：

> 以后新增一个板块（剪贴板、笔记、语音…），安卓端**只允许改一个文件**（注册表加一行），
> 其余全靠框架自动接上：导航入口、图标、标题、绑定校验、身份注入、错误处理、模块启停。

这与桌面侧《[移动互联架构现状与目标](../移动互联架构现状与目标.md)》第六节的"热插拔验收标准"是同一个思想，
只是验收对象从"三端"收敛到"安卓端内部"。

### 1.4 构建链路上的坑（已踩过并解决，换机器会再遇到）

| 坑 | 现象 | 解决 |
|---|---|---|
| **JDK 25 不能用** | `Unsupported class file major version 69` | 显式 `JAVA_HOME` 指向 JDK 21 |

#### ⚠️ 关于明文 HTTP 放行（纠正了一个常见错误配置）

契约 §8.5 只说要配 `network_security_config.xml`，但**没有说怎么配才对**。实测查证后确认：

`<domain>` 对 IP 地址**只做精确匹配，且不支持 CIDR / 通配符**。以下写法**全部无效**：

```xml
<domain>192.168.0.0</domain>     <!-- 匹配不到 192.168.1.5 -->
<domain>192.168.*.*</domain>     <!-- 不支持 -->
<domain>192.168.0.1/16</domain>  <!-- 不支持 -->
```

而局域网 IP 由桌面端运行时决定、每次「一键直连」都可能变（契约 §8.5-2 要求**不要缓存 IP**），
**无法在构建期枚举**。因此本工程采用 `base-config cleartextTrafficPermitted="true"`，
并在该文件里写明了安全权衡（云端地址仍硬编码为 `https://`，明文只可能出现在局域网链路）。

> 这一条已在 `network_security_config.xml` 内注释留档，**请勿改回"看起来更严谨"的逐段写法**——
> 那会导致局域网控制**静默失败**，正是契约反复警告的坑。

## 2. 框架设计（本阶段的核心交付）

### 2.1 分层架构

```
android/app/src/main/java/com/wanan/shortcut/
├── ShortcutApp.kt              Application：DI 容器 + 全局初始化
├── MainActivity.kt             唯一 Activity（Compose 承载 + 系统栏）
│
├── core/                       ① 地基：与业务无关，只被依赖、不依赖业务
│   ├── result/                 统一结果类型（区分"传输失败"与"业务失败"）
│   │   └── ApiResult.kt
│   ├── net/
│   │   ├── ApiClient.kt        api.php：恒 200，读 success 字段
│   │   ├── FileClient.kt       file.php：真实 HTTP 状态码
│   │   ├── HttpEngine.kt       OkHttp 单例、超时、UA、UTF-8 强制
│   │   └── Endpoints.kt        域名/路径集中（唯一改地址的地方）
│   ├── identity/               ② 身份层：全局唯一身份持有者
│   │   ├── IdentityStore.kt    DataStore：bindId/mobileToken/deviceKey/deviceName
│   │   ├── DeviceKey.kt        随机 24 hex，首次生成后永久持久化（契约 §3.4）
│   │   └── IdentityProvider.kt 当前身份快照 + 失效广播（单一真相）
│   ├── error/
│   │   ├── ErrorMapper.kt      服务端文案 → 客户端动作（见 §2.3）
│   │   └── AppError.kt
│   └── security/
│       └── TokenBox.kt         mobileToken 加密存储（EncryptedSharedPreferences）
│
├── framework/                  ③ 模块框架：本文的重点
│   ├── ModuleContract.kt       ★ 板块契约（唯一需要实现的东西）
│   ├── ModuleRegistry.kt       ★ 注册表（加板块 = 这里加一行）
│   ├── ModuleManifest.kt       服务端 module.list 的映射模型
│   ├── ModuleHost.kt           按契约统一渲染：标题/图标/设置/入口
│   └── framework/…
│
├── feature/                    ④ 业务板块（每个板块一个包，互不依赖）
│   ├── bind/                   绑定（框架级，但按模块规范写）
│   ├── home/                   首页：由 module.list 数据驱动
│   ├── settings/               设置
│   ├── taskwall/               ← P1 填
│   └── control/                ← P2 填
│
└── ui/                         ⑤ 通用 UI：主题、组件、导航宿主
    ├── theme/
    ├── components/
    └── nav/
```

**依赖方向铁律：`feature/* → framework/* → core/*`，绝不反向。**
板块之间**不互相 import**；需要协作走 `core/` 或事件总线。

### 2.2 板块契约（加板块只写一个文件）

```kotlin
interface ShortcutModule {
    /** 与 server/sync/modules.json 的 id 对齐；服务端没返回该 id 时不显示 */
    val id: String

    /** 本地兜底元数据（服务端 module.list 不可达时仍能显示入口） */
    val meta: ModuleMeta

    /** 入口页面 */
    @Composable fun Screen(nav: ModuleNavigator)

    /** 可选：设置页分片（不实现则不出现该板块的设置项） */
    @Composable fun SettingsSection(): Unit = Unit

    /** 可选：模块自己关心的 WS 消息 / 生命周期回调 */
    fun onRealtimeMessage(msg: RelayMessage) = Unit

    /** 可选：模块自己的前台服务需求（控制板块用） */
    val foregroundService: ForegroundSpec? get() = null

    /** 可选：模块级权限声明（通知、存储…），框架统一申请 */
    val permissions: List<String> get() = emptyList()
}
```

**框架自动完成的事**（板块作者一行都不用写）：

1. 用 `id` 向服务端 `module.list` 对账：`enabled=false` 或无 `entry` → 不显示入口；
2. 比对 `minAppVersion` 与自身 `BuildConfig.VERSION_NAME` → 版本过低时展示"请升级"而非崩溃；
3. 首页/侧边栏的卡片：图标、标题、描述来自 `module.list`（本地 `meta` 只兜底）；
4. 每次 API 调用自动注入 `bindId` + `mobileToken`；
5. 身份失效（`移动端绑定已失效，请重新绑定`）→ 自动清本地身份 + 跳绑定页，板块无感；
6. 统一 loading / 空态 / 错误态 / 重试；
7. 按需申请模块声明的权限、按需起停前台服务。

**验收方式（可自证）**：写一个 `feature/_demo/DemoModule.kt`（假板块），
在注册表加一行 → 首页立刻多一张卡片、点进去是它的页面、设置页多一段；
**不改任何其它文件**。做不到就说明框架没搭对。

### 2.3 两种失败语义（契约 §1.2，框架必须从底层就分开）

这是**最容易写错**的地方，必须由框架统一处理，不能让每个板块自己判断：

| 入口 | HTTP 状态 | 判成败依据 | 框架处理 |
|---|---|---|---|
| `api.php` | **恒 200** | 读 `success` 字段 | `ApiClient` 返回 `ApiResult.Ok(data)` / `ApiResult.BusinessFail(message)` |
| `file.php` | **真实状态码**（400/403/404/405/500） | HTTP 状态码 **且** `success:false` | `FileClient` 返回 `ApiResult.TransportFail(code, message)` |

调用方**永远只 match `ApiResult`**，不接触 `success` / 状态码。

### 2.4 错误文案 → 动作映射（框架统一，板块不重复）

按契约 §1.3，**错误文案是字符串契约**，必须按文案分支：

| 服务端 message | 框架动作 |
|---|---|
| `移动端绑定已失效，请重新绑定` | 清本地身份 → 跳绑定页（全局一次） |
| `绑定身份无效` / `缺少 bindId` | 同上 |
| `…过于频繁…` | 提示"操作太快了，稍后再试"+ 退避重试 |
| `绑定码无效` | 停留在绑定页，提示换一个码 |
| `本绑定已绑定 N 台手机（已达上限）…` | 原样展示（含"去电脑端移除设备"的指引） |
| 其它 | 原样 toast |

### 2.5 身份层的三条硬规则

1. **`deviceKey` 必须持久化**：随机 24 位 hex，首次生成后永久保存（等价 Web 端 `shortcut-device-key-v1`）。
   **不用 `ANDROID_ID`**（可能变化）。实测已确认：不带它重绑会堆僵尸设备直至占满上限。
2. **`mobileToken` 加密存储**：`EncryptedSharedPreferences`（`TokenBox`），不落明文。
3. **身份只有一处真相**：只有 `IdentityProvider` 能读写；板块一律通过框架拿到，不自己读 DataStore。

### 2.6 预留扩展位（现在不实现，但结构要能接上）

| 未来能力 | 预留方式 |
|---|---|
| OPPO 推送 | `core/push/PushGateway.kt` 接口先留空实现；`ModuleRegistry` 支持 `onPushPayload()`；设置页留"消息通知"分组 |
| 更多实时指令 | `core/realtime/` 里 `RelayCommand` 用密封类，白名单 11 个指令（契约 §7.4）一次写全 |
| 新协议版本 | `core/net/Protocol.kt` 存 `PROTOCOL_VERSION`，启动时与 `module.list` 的 `protocolVersion` 比对，不一致只警告不拒绝（服务端不校验，契约 §4.1） |
| 多语言 | 文案走 `strings.xml`，不硬编码中文（本期只有中文，但别散落） |

### P1 · 第一个真板块：任务墙（验证框架）✅ 已完成（2026-10-13）

- `feature/taskwall`：任务列表、新建任务（标题/长文本/提醒时间/目标墙）、`push` → 桌面、`pull` 拉取、`ack` 确认。
- `core/util/DateFormats`：契约 §1.2 的**两种时间格式**分别处理。
- **本阶段的真正目的**：验证 `ModuleContract` 在真实板块上是否够用。

#### 框架自证结果

加入任务墙板块**只改了 `Modules.kt` 一行**（外加 `AppContainer` 一行 ViewModel 构造），
未触碰首页、导航宿主、`AndroidManifest`、设置页。板块文件里**没有**出现
`bindId` / `mobileToken` / 移动端绑定已失效 / HTTP 状态码判断 —— 全部由框架承担。

> **发现并补上的框架缺口（1 处）**：`ModuleNavigator.to()` 在 P0 只是空实现，
> 板块无法在自己的多个页面间跳转。已在 `ModuleHostScreen` 补上真正的子路由
> （`rememberSaveable` + `LocalModuleSubRoute` CompositionLocal），
> 板块只声明子页名，不承担导航框架复杂度。这正是"先用框架再补框架"的预期路径。

#### 线上实测（2026-10-13）

| 调用 | 结果 |
|---|---|
| `board.list` | ✅ `{"success":true,"boards":[]}` |
| `push`（longText + reminder） | ✅ 返回 `taskId`；`deliveredRealtime:false`（桌面离线） |
| `pull` | ✅ 返回任务，`longText/details/reminderAt` 全部原样回读 |
| `ack` 真实 taskId | ✅ `{"success":true,"removed":1}`；再 pull → 空列表 |
| `push` 空文本 | ✅ `任务标题不能为空` |
| `push` board≠taskwall | ✅ `暂不支持的板块` |
| `reminderEnabled=true` + 非法时间 | ✅ `提醒时间格式无效` |
| `ack` 空数组 | ✅ `缺少待确认任务` |

#### 单测新增 8 个（总数 35，全绿），又抓到 2 个真 bug

1. **`SimpleDateFormat` 默认宽松**：`2026-13-45T99:99:99` 被"进位"成合法日期，
   解析失败被吞掉 → 界面显示离谱时间。已改 `isLenient = false`。
2. **`XXX` 模式无法解析不带偏移的时间**：服务端少数字段不带时区，
   直接解析失败。已改为"带偏移 → 不带偏移"两段尝试。

### P2 · 电脑控制（含局域网直连 + 前台服务）

- `core/realtime`：`control.ticket` 换票（**一条连接只换一次**）→ WS 首帧 `auth` → `{t:'api'}` 发指令 → 按 `id`（String 归一化）过滤 `api-res`。
- 硬约束（契约 §7.6）：单帧 ≤64 KiB、回 `pong`、25 秒应用层 ping、3 秒重连、60 秒半死检测、指令 8 秒超时。
- 控制面板：打字 / 虚拟键盘 / 组合键 / 触控板 / 滚轮 / 剪贴板。
- **局域网一键直连**：经云端 WS 问 `/api/lan-entry` → 拿 `token` 直连 `http://<ip>:9823`（**每次重新询问，不缓存 IP**）。
- **前台服务 + 常驻通知**（用户明确要求后台可用）。

### P3 · 文件快传

- `transfer.fileInit` → `file.php?action=uploadChunk`（multipart 二进制、**0-based 连续**、分片大小回读服务端）→ `transfer.fileComplete`。
- 下载：本人身份 或 `dl_` 一次性令牌（900 秒）。
- 断点续传用 `blob.status`。

### P4 · 推送（待用户重启讨论）

- 依赖桌面侧先实现 `push.register` + OPPO 网关；安卓侧已在框架预留接入位。
